# 任务 G · 黄条里的「+ 一键新建该客户」

> 日期：2026-10-19
> 起因：用户实测 261 万合同，OCR 认出「湖南华邦建设有限公司」，系统正确提示"未匹配到客户"，
> 但下拉里**确实没有这家**（从没录过档案）→ 用户卡在这一步，得先跑去基础资料建客户再回来重识别。
> 结论：把"缺档案"这个断点就地补上 —— 黄条里给一个按钮，弹精简表单，建完自动选中。
> 验证：界面台 **30/30**、反证 4 组全部按预期变红、任务 F 全台未回退

---

## 1. 改之前长什么样

```
客户 *  [ 湖南华邦建设有限公司 ▾ ]
        ┃ 未匹配到系统客户「湖南华邦建设有限公司」，已保留识别到的名称。
        ┃ 请点开下拉手动选一次，否则保存会被拦。
```

问题：这句话**只说了"不行"，没说"怎么办"**。用户能做的只有两种，都很别扭：

1. 去「基础资料 → 客户档案」建一条，回来重新识别（识别要等 45~322 秒）；
2. 在别的页面建好，再回来这里重新选。

而实际情况是：**用户就是要在这张合同上用到这个客户**，档案只是它的副产品。

## 2. 改之后

```
客户 *  [ 湖南华邦建设有限公司 ▾ ]
        ┃ 未匹配到系统客户「湖南华邦建设有限公司」，已保留识别到的名称。
        ┃ 请点开下拉手动选一次，否则保存会被拦。
        ┃ + 一键新建该客户            ← 蓝色链接按钮
```

点开是一张**精简表单**（560px 宽，只占一屏的一半）：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| 客户名称 * | **OCR 认出的名字**（已聚焦全选） | 想改名直接打；不改就 Tab 到保存 |
| 客户编码 | 空 | placeholder 写明"留空自动生成（CUS + 日期 + 流水）" |
| 联系人 / 联系电话 / 地址 / 备注 | 空 | 全可选，以后到基础资料补 |

保存 → `POST /customers`（后端 `code` 留空走 `_next_doc_no` 自动生成）→ 返回整条档案 →
**自动关闭弹窗、自动选中、黄条消失、红条消失、顶部给回执**：

> 已新建客户「湖南华邦建设有限公司」并选中

## 3. 几个刻意的设计（都是为了不再产生新问题）

### 3.1 三条管道必须一起写，少一条就还是"假选中"

```js
setForm((prev) => ({ ...prev, party_id: id, party_name: name }));  // ① 选中 + 显示
setCustomers((prev) => [item, ...prev.filter(...)]);                // ② 下拉立刻可见
setPartyHint(null);                                                // ③ 黄条消失
```

只写 ①：下拉里看不到它（要刷新页面），用户以为没建成。
只写 ②：保存仍报"请选择客户"（就是任务 F 那个 Bug 2）。

### 3.2 不让重复建档：先查同名再 POST

保存前调用父组件注入的 `findExisting(name)`（内部就是任务 F 的 `findPartyByName`）：

- 命中 → **不发请求**，直接选中那一条，回执写「已直接选中（没有再建一条重复档案）」；
- 未命中 → 才 POST。

两家同名客户是最难查的一类脏数据（对账、开票、催款全都对不上），所以这里宁可少建一条。

### 3.3 按钮只在"未匹配"（黄条）时出现

蓝色提示是"按简称猜中的，请确认"——那时档案**是存在的**，再给"新建"入口只会诱导用户建一条重复的。所以按钮只在 `tone === 'warn'` 时渲染。

### 3.4 字段容器从 `<label>` 改成 `<div>`

原来客户字段是 `<label className="cledger__field">`。`<label>` 里放 `<button>` 会触发 label 的默认行为（激活关联控件）—— 点"一键新建"可能顺带把下拉顶开。交互元素不能包在 label 里，所以改成同 class 的 `<div>`（外观零变化）。

### 3.5 弹窗挂在合同弹窗**外面**（同层），不是里面

合同弹窗是 `.modal-card.modal-wide`，带 `overflow: auto`。把新弹窗塞进去，它会跟着一起滚、还可能被裁掉。所以放在合同弹窗的闭合标签之后、作为兄弟节点渲染。

### 3.6 Esc 只关最上面这层

`keydown` 用**捕获阶段** + `stopPropagation`，否则按 Esc 会把下面的合同弹窗一起关掉，用户刚识别的结果全没了。

## 7. 已知边界

1. **只补了"客户/供应商"，没补商品**：明细里若出现档案里没有的商品，仍是"只显示名字不绑 id"。同样的模式可以套（`POST /products`），但商品字段多（单位、规格、分类），精简表单会长一倍 —— 单独排期。
2. **小弹窗不建分类**：新建的档案落在"未分类"下，要归类得去基础资料。
3. **编码冲突**：后端只挡编码重复（400 中文提示），不挡同名；同名由前端 `findExisting` 挡（见 3.2）。
