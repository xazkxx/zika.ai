# 浩技云样板 对照我们 ERP —— 关联开发可行性方案

> 结论：**可以按浩技云的样板开发，而且底座已经铺好了。** 缺口集中在「单据表」和「页面」两层，
> 不在架构层——因为进销存最难的三个关联（单据→库存、单据→财务、单据→打印/导出）我们已经做成
> 注册表机制，新模块只要"登记一下"就能挂上去。真正需要新写的只有 27 个模块，其余 53 个页面
> 要么已有、要么只差一个列表页、要么用现有数据聚合就能出。

## 二、关联底座盘点 —— 6 个"插座"已经装好

这是"能不能按样板关联开发"的核心答案。进销存系统的难点从来不是页面，
而是**一张单据要同时牵动库存、财务、打印、导出、权限五条线**。我们把这五条线都做成了注册表：

| 插座 | 位置 | 现状 | 新模块怎么挂 |
|---|---|---|---|
| ① 财务事件字典 `DOC_TYPES` | `app/models/finance.py` | **21 种**，含 `purchase_return` / `sales_return` / `inv_check` / `inv_scrap` / `inv_overflow` / `inv_transfer` / `production_issue` / `production_in` / `production_wage` / `outsourcing` / `expense` / `contract` | 待建模块的类型**几乎都已经登记**，直接引用 |
| ② 库存流水溯源 | `inventory_transactions.related_type / related_order_id / doc_no` | 采购→inbound、销售→outbound 已跑通 | 新单据写一条流水，带上 related_type 即可自动进库存&支持删单冲销 |
| ③ 财务流水多维 | `financial_transactions.related_type + product_id / warehouse_id / project_id + direction / period` | 已有期间(YYYY-MM)索引 | 新单据按"审核后自动写流水"规矩挂上去 |
| ④ 打印注册表 `_PRINT_KINDS` | `erp.py:2995` | 采购订单/采购入库/销售开单/送货单 + 购销合同 | 一行登记 `_PRINT_KINDS["xxx"] = (名称, spec, 参数)` |
| ⑤ Excel 导入导出注册表 | `app/services/excel_io.py` 的 `COLUMNS / TITLES / KEY_FIELDS` | products / customers / suppliers / warehouses / opening-stock | 加一组列定义即可获得模板+预检+导入导出 |
| ⑥ 菜单框架 + 待建位 | `frontend/src/App.jsx` 的 `menuGroups`（`todo: true`） | 32 个待建位已按浩技云摆好 | 去掉 `todo` + 加一个 `selectedTab === 'key'` 分支 |

> 换句话说：**菜单已经摆成浩技云的样子了，插座也已经通电了，剩下的是把电器插上去。**

## 四、新模块的标准开发模板（抄现成的，5 步）

因为我们把关联都收敛成了注册表，新增一个模块的路径是**固定的**：

```
第1步  建表      app/models/xxx.py     ← 抄 purchase_order.py 的头+明细结构
第2步  登记事件  finance.py DOC_TYPES  ← 大部分类型已经写好了，直接引用
第3步  写接口    erp.py 加 6~10 条     ← 抄 contracts 的 10 条（列表/新建/详情/PATCH/删除/转单/打印）
第4步  挂插座    打印 _PRINT_KINDS、Excel COLUMNS（按需）
第5步  开页面    App.jsx 去掉 todo + 加 selectedTab 分支  ← 抄现成列表页
```

**库存类模块额外第 3.5 步**：写一条 `InventoryTransaction`，填 `related_type / related_order_id / doc_no`
→ 自动进库存、自动支持"删单冲销"、自动出现在变动查询里。
**财务类模块额外第 3.5 步**：遵守既有规矩——「**单据审核后由系统自动写流水，人工只能登记收付款与费用**」。

## 五、需要留意的 4 个坑（照抄会出问题的地方）

1. **采购订单 / 采购入库 我们是一张表，浩技云是两张页。** 浩技云 `emkMInStorageController` 用
   `?list`（入库）和 `?list2`（订单）区分。我们目前共表——建议加 `doc_type` 判别字段而不是拆表，
   这样已有 89 个接口和打印注册表都不用动。
2. **浩技云的"字段表管理 / 打印字段表"是它的动态表单机制**（改字段不用改代码）。我们是代码注册
   （`COLUMNS` / `_PRINT_KINDS`）。**不建议照抄**——那会引入一整套元数据引擎，收益远小于复杂度。
   建议改成"模板配置表 + 固定渲染器"，够用。
3. **组合拆卸别新建结构**，直接复用 `BillOfMaterial` 的父子关系（`parent_id` + `cascade` 已就绪）。
4. **季报/年报的聚合要小心**，16 张报表如果每张都全表扫会拖慢系统；`period` 已有索引，
   按 period 预聚合是最省的做法。
