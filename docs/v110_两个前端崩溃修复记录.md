## 问题 1：商品档案右侧列表消失

### 真凶不是 React 崩溃，是**分栏组件的子元素计数**

`components/resizable-layout/ResizableLayout.jsx` 里原本是：

```js
const items = Children.toArray(children);
const resizable = items.length === 2;          // ← 这里
if (!resizable) return <div className="management-grid">{children}</div>;
```

而 `.management-grid` 的轨道是 `var(--mgrid-left) 16px minmax(0,1fr)`
（264px / 16px / 1fr）。一旦子元素变成 3 个（我在商品页给列表加了「导入」弹窗+
「批量移动」弹窗，弹窗打开时是非 null 的），`resizable` 变 false：

- 手柄被丢掉 → 但轨道还是三条；
- 于是「左卡片 → 264px 轨」「右卡片 → **16px 手柄轨**」→ 列表被压成 16px = 看起来整块消失；
- 更糟的是**弹窗关掉也回不来**（轨道由 CSS 定，不会自己复原）。

实测数据（headless Chrome，1440×900，商品档案，开一次导入弹窗再 Esc）：

| 时刻 | grid 子元素 | 列轨道 | 列表宽度 | 行数 |
|---|---|---|---|---|
| 修复前·打开弹窗前 | card / handle / card | 264/16/722 | 722 | 262 |
| 修复前·关掉弹窗后 | card / **card(16px)** | 264/16/722 | **16** | 262（看不见） |
| 修复后·关掉弹窗后 | card / handle / card | 264/16/722 | 722 | 262 |

### 改法（组件层收口，不是逐页打补丁）

只认**前两个**子元素当左右栏，其余（弹窗、抽屉这类 fixed 覆盖层）挂到栅格外：

```js
const panes = items.slice(0, 2);
const extras = items.slice(2);
const resizable = panes.length === 2;
...
return (<>
  <div className="management-grid mgrid--split" ...>{panes[0]}<handle/>{panes[1]}</div>
  {extras}
</>);
```

这样"页面上多挂一个弹窗"永远不会再动到分栏。商品/仓库/员工三个档案页都受此保护。

## 问题 2：销售退货操作列按钮挤到屏幕边框

### 根因（两个叠在一起）

1. **CSS**：`.row-actions { white-space: nowrap }` + 4 个按钮 + 表格 `width: 100%`，
   单元格撑不住时整张表比容器还宽，最后一格溢出卡片、贴着视口右边；
   面板又没有 `overflow`，于是"粘在屏幕边框上"。
2. **业务**：4 个按钮对所有状态一视同仁（`disabled` 只是灰掉，没隐藏），
   草稿单上也摆着「作废」——这是账务入口，不该给。

### 改法

**① 操作列按状态收敛**（页面里写死，不靠灰按钮暗示）：

| 单据状态 | 操作列 |
|---|---|
| 草稿 `draft` | 打印 / **编辑** / **删除**（草稿没落过账，删了就是删了，不给作废） |
| 已退货 `submitted` | 打印 / **反审核** / **作废**（**不给删除**：删单会连带撤账） |
| 已取消 `cancelled` | 只留打印（留痕用） |

**② 布局**：列表从 7 列砍到 5 列（业务员、退货原因收进 `title` 悬停提示），
`table-layout: fixed` + `<colgroup>` 百分比列宽（24/17/16/14/29），
`.table-panel { overflow-x: auto }`，分栏比例按页面给到 36/64。
实测三档宽度：**1440 / 1280 / 1920 全部 actionInside = true，无横向滚动**；
只有客户名会截断（带悬停全名），单号 / 金额 / 状态 / 按钮全都不截断。

**③ 顺带补上「编辑」**（原来只有新增）：草稿单可以「编辑」把它载回上方表单，
提交走 `PATCH /sales-returns/{id}`（后端四路径早就写好了：草稿改动不碰账）。
实测：载入 → 改 → 保存修改，单据金额/明细不变、状态仍为草稿、库存与应收没动。

## 如果强刷后还有问题

1. **先确认版本号**：左下角必须是 `v131 · 20261021-1743`。
   还是 v109/v110 说明 Service Worker 没换：
   DevTools → Application → Service Workers → **Unregister** → `Ctrl+F5`。
2. **商品档案还是空**：按 F12 → Console，看有没有红字；
   再看 Elements 里 `.management-grid` 是不是只有两个子元素（应该有 3 个：卡片/手柄/卡片）。
   如果只有 2 个且第二个宽度 ≈16px，把 `grid-template-columns` 的值发我。
3. **销售退货按钮又跑出去**：DevTools 选中 `<td class="row-actions">`，
   看它的 `getBoundingClientRect().right` 是否大于 `.table-panel` 的 right。
   大于就是又漏了宽度约束（比如有人给表格加了新列没算进 colgroup）。
4. 临时排查脚本：`node /tmp/dbg_cols.cjs` 这类探针都在会话里，可直接改端口跑。
