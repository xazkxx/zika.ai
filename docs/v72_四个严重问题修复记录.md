## 问题 1：反审核会联动冲销库存和应收（业务灾难）

### 现象
点「反审核」，单据退回草稿的**同时**，系统悄悄撤回了这张退货单加过的库存、
并把冲减过的应收加回来。改两次就出入两次，全程无提示。

### 根因
一个函数 `_sync_sales_return_ledger()` 同时承担了「加账」和「撤账」，
而它被"改状态"这条路复用。于是"我要回去改一下"和"这张单不要了"变成了同一个动作。

### 改法
拆成两个函数，且**撤账只有一个入口**：

| 函数 | 职责 | 谁调它 |
|---|---|---|
| `_sales_return_apply_ledger(db, item, rows)` | 只加、只加一次（幂等查流水）、只有 `submitted` 才加 | 创建/审核 |
| `_sales_return_red_flush(db, item, rows)` | 先冲旧、再落新 | **只有**「改已落账单」和作废 |

- `PATCH /sales-returns/{id}/status` → **只写状态**，账一个字都不碰；
- 新增 `POST /sales-returns/{id}/void` → 唯一会反向冲账的入口，落 `cancelled`，写备注留痕，幂等；
- `posted_before` 改成**查流水**而不是看状态（历史单流水被清掉时状态不可信）；
- `PATCH /{id}` 收口四条路径（先判"这次改完该不该有账"，再判"原来有没有"），
  并拦住 `status='cancelled'`（400）。

### 另外补上的一个反向 bug
原收口顺序是「先看原来有没有账 → 再决定冲不冲」，导致
**草稿状态下改明细会把上一版账红冲掉**（单据说 350、账上空了）。
验证脚本第一次跑就命中了（2 FAIL）。现已改为先判 `will_post`。

### 前端
- 「反审核」：无弹窗、提示文案明说"账没有变"；
- 「作废」：红色按钮 → `confirmDanger()` 二次确认 → **必填原因**（空则按钮禁用）→ 才调接口；
- 宿主未挂载时 `confirmDanger` 返回 `{ok:false}`（**拒绝**），
  与 `confirmPrint` 未挂载返回 `true`（放行）刻意相反 —— 红冲不可逆，宁可点了没反应。

### 验收
`scripts/verify_phase2_sales_return.py` 按新语义重写，**47 PASS / 0 FAIL**，含：
反审核账不动 / 再次审核幂等 / 草稿改明细账不动 /
改状态接口不许置 cancelled / 作废后账清空 / 重复作废幂等 / 作废单不许编辑。

## 问题 3：供应商档案点某条记录整页白屏

### 现象
点「中铁一局集团」→ 整个页面白屏，无任何报错。

### 根因（不是 null 字段）
`ReferenceError: Cannot access 'visible' before initialization` —— **TDZ**。
`exportRows = pickedSomething ? visible : list` 写在了 `visible` 的 `useMemo` **之前**。
`const` 的暂时性死区在函数组件每次渲染时真实生效，一抛错 React 卸载整棵树 → 白屏。

### 改法
- 把 `pickedSomething / exportRows / runExport` 整块移到 `visible` 之后；
- 新增 `components/ErrorBoundary.jsx`：`getDerivedStateFromError` + `componentDidCatch`，
  支持 `label`（哪一块出错）与 `resetKey`（换页自动复位），
  复制按钮 `clipboard` 优先、`execCommand` 兜底；
- 双层挂载：`main.jsx` 顶层（整机）+ `App.jsx` 页面级（`resetKey={selectedTab}`）。

### 验收
`中铁一局集团` / `国家电网` 两条记录点击后均不白屏，69 行列表完好，
`[data-error-boundary]` 不存在，pageerror 为空。

## 额外收获：两个"构建能过、运行时白屏"的坑

清理死代码时，`const authHeaders = ...`（被全站 90+ 处调用）和 ctx 里的
`setExcelBusy/...` 因为紧挨着被删代码块，被一起删掉了。
**`vite build` 完全没报错**（esbuild 只做语法/打包，不做未定义变量检查），
后果是**整个主界面白屏**。这两次都是在浏览器里才发现的。

因此新增 `scripts/check_undefined_refs.cjs`：
用项目自带的 `@babel/parser` 逐文件解析 AST，找出
「被调用 `foo()`」「被当组件 `<Foo/>`」「简写属性 `{ foo }`」「数组元素 `[foo]`」
但本文件没有绑定的标识符。**已接进 `npm run build`，构建不过就不出包。**

```
"build": "node ../scripts/check_undefined_refs.cjs && vite build"
```

当前状态：`OK 129 个源文件，被调用的标识符全部都有定义。`

### 顺带发现的真 bug（合同非法类型可静默入库）

`ContractCreate` 的 `model_validator(mode="after")` 会**无条件**把 `contract_type`
回写成 `sales`/`purchase`。于是传 `contract_type="lease"`（租借合同）时，
路由里的 `not in CONTRACT_TYPES` 永远不成立 → **201 建库，界面看不出任何异常**。

已修：`_sync_direction` 只在类型**合法**时才回写，非法值原样放行，
由路由返回中文 400「contract_type 只能是 sales 或 purchase」。
（没有在 schema 里 `raise ValueError`：那会变成 422 的英文 errors 数组，不符合本项目"中文 400"的对外口径。）
