# 三模块状态管理根治（2026-10-22 · 第二轮）

> 用户口径：**停止缝缝补补**，把"左树 ↔ 右表"的状态管理在底层收口。
> 版本 **v161 · 20261022-1153**（PWA `erp-pwa-v161`），纯前端。

---

## 一、找到了什么：三个把右表变成空白的机制

### 1. 选中 id 的"数字 / 字符串"双形态

`categoryScope = subtreeIds(index, categoryId)` 生成的是**一组 id**，而行过滤用的是
`scope.has(Number(row.category_id))`。只要 `categoryId` 是字符串（`data-node-id` 属性、
URL、localStorage 都是字符串），Set 里就是 `"13"`，而比较的是 `13` —— **永远不命中**，
右表 0 行。树那边照常高亮（它是按字符串/数字都能比的），于是"左边点得好好的，右边一片空白"。

**根治**：scope 同时收 `Number(id)` 与原始值两种形态；行过滤统一 `Number()` 后再比。

### 2. 选中的分类已经不在索引里

树还没加载完 / 别处删了这个分类 / 索引是旧的一版 —— 这时按 id 过滤必然是 0 行。
**根治**：新增 `staleSelection` 判定，选中项不在索引里时**退化成看全部**，并在副标题里
说明，"宁可多显示，也不要给一片空白"。

### 3. 右表被分类树的 loading 遮成骨架屏

上一轮我把 `loading={cats.loading}` 接到了右表。分类树每次 `reload()`（拖拽后必刷）
都会把已有数据换成骨架 —— 骨架里**没有操作列按钮**，看起来就是
"列表空白 + 操作列空无一物 + 只剩表头"。这一次的"没有编辑按钮"就是这么来的。

**根治**：右表**不接**分类树的 loading。右表数据是本地过滤的，本来就不需要骨架。

---

## 二、操作列：为什么现在一定在

- 操作列是 `columns` 里的最后一列，`render` 是固定的按钮组，与"有没有数据"无关：
  **有数据行就必然渲染按钮**；没有数据时表头「操作」仍在（表头与 tbody 是分开渲染的）。
- 唯一会"看起来没有按钮"的情形就是上面第 3 条（骨架屏替代了真实行），已掐掉。

> 顺带说明：行内双击编辑是**补充**，不是替代。显式的「编辑 / 删除」按钮一直保留，
> 客户、供应商、商品三个模块都一样。

---

## 三、空状态文案：三种情况必须三句话

| 场景 | 客户/供应商 | 商品 |
|---|---|---|
| 还没选分类 | 请先在左侧选择一个分类 | 同左 |
| 选了但这一类确实没有 | **这个分类下还没有客户**（+「查看全部」） | **这个类别下还没有商品**（+「查看全部商品」） |
| 有数据但被关键词过滤掉了 | 没有匹配的客户（+「查看全部」） | 没有匹配的商品（+「清空搜索」） |

以前后两种共用一句，用户看到"请先选择一个分类"会以为是拖拽没生效 —— 这正是本轮报障的
心理来源。

## 四、验收：新增三模块巡检脚本

`scripts/verify_three_modules_patrol.cjs`（**16 / 16**，真实浏览器）：

```
PASS  【客户】点「全部客户」右表有数据  — 29 行
PASS  【客户】表头有「操作」列  — /编码/名称/分类/级别/业务员/电话/邮箱/操作
PASS  【客户】每行都有 编辑+删除  — edit=true del=true
PASS  【客户】没有被骨架屏遮住  — skeleton=0
PASS  【客户】点各一级分类：不出现"左边有右边空"  — 异常 0 次
PASS  【供应商】…（同上 5 条，70 行）
PASS  【商品】…（同上 5 条，262 行）
PASS  全程零页面错误
```

它逐个点**每一个一级分类**，并断言：要么有数据，要么明确说"这个分类下还没有…"，
**绝不允许**出现「请先选择一个分类」；同时校验每一行都有编辑+删除、表头有操作列、
全程没有常驻骨架。

其余回归：

| `verify_partner_linking`（真实拖拽+行内编辑） | 11 / 11 |
| `smoke_run`（54 菜单） | 零 pageerror / console.error |
| `check_undefined_refs` | 136 文件全绿 |

数据卫生：清掉了复现用的 1 条测试客户（`塞拉测试-*`），客户回到 28 条。
