# 档案表单字段换血 + 左侧树全局模糊搜索（2026-10-23）

两件事一起交付：
**① 客户/供应商弹窗的字段重排（删客户级别、补开票四列）**；
**② 客户/供应商/商品三个页面左侧树的搜索升级（能搜到档案、自动展开、不剩空壳、清空复原）**。

---

## 一、档案表单字段

### 1. 改了什么

| 动作 | 字段 | 说明 |
|---|---|---|
| 删 | `level`（客户级别） | 业务上没人维护，还是自由文本（"重要客户"这类），占一行没价值 |
| 加 | `tax_no`（纳税人识别号） | 库里早就有（2026-10-22 加的），表单一直没放出来 |
| 加 | `bank_name`（开户行） | 同上，库里已有 |
| 加 | `bank_account`（银行账号） | 同上，库里已有 |
| 加 | `invoice_phone`（开票电话） | **新列**，客户/供应商各一列，可空幂等迁移 |

> 为什么开票电话要单独一列：开票信息里的电话常常是财务座机，与业务联系的手机不是同一个号。
> 合同抬头/开票资料要用**财务那个号**，混在一起会两边都不对。

### 2. 迁移

`app/main.py` 的 `CUSTOMER_ADDITIONS` / `SUPPLIER_ADDITIONS` 各追加一行
`"invoice_phone": "VARCHAR(30)"`（只追加键，不重排字典 —— 这是幂等迁移的唯一来源）。
实测已建出列：

```
customers.invoice_phone  ✓
suppliers.invoice_phone  ✓
```

### 3. 自动带出（两条链）

* **合同正文**：`resolve_contract_document_payload` 原来只在 `party_name` 为空时才反查档案 ——
  而合同表单里名称早就选好了，于是**税号/开户行/账号从来没进过正文**，打出来的抬头永远是空的。
  现在改成"按字段各自补空缺"，与名称无关，并补了 `party_bank_name / party_bank_account`；
  抬头电话顺序：**合同上填的 → 开票电话 → 联系人电话 / 手机**。
* **合同创建**：`create_contract` 也会把开票电话写进 `party_phone` 快照（同一个优先级）。
* **发票 OCR**：匹配一直是"税号优先、名称兜底"（`_resolve_customer_id`），
  这次让税号**能录进档案**（以前只能从接口塞），OCR 的税号匹配才真正可用。
* **智能识别上传**：客户档也允许回填 `bank_name / bank_account / invoice_phone`
  （原来客户分支会把开户行/账号丢掉），并新增「开票电话」的解析。

## 二、左侧树搜索

### 1. 原来的问题

* 客户树只能搜**分类名**：搜"周广平"什么都出不来 —— 客户是挂在分类下的另一份数据
  （`rowsByCategory`），`searchNodes` 只走 `children`。
* 商品树**根本没有搜索框**。
* 搜索后没命中的分支还留着壳；清空后树停在"搜索时摊开的样子"。

### 2. 现在的规则（三个树一致）

| 规则 | 实现 |
|---|---|
| 双向模糊匹配 | 分类名 + 挂在它下面的档案（客户/供应商：名称/编码/联系人/电话/业务员/简称/税号；商品：名称/SKU/规格/所属类别名） |
| 命中自动展开 | 命中节点（或"有档案命中的分类"）的**整条祖先链**强制展开（不写进 `expanded`/`collapsed`） |
| 空壳清理 | 可见集合 = 命中 + 祖先；没命中的兄弟分支一个都不渲染；全无命中时给"没有匹配…"的提示 |
| 高亮 | 分类名里的命中片段用 `<mark>`；命中的**档案行**黄底 + 左侧竖条（按联系人命中时名字里没有关键词，必须靠行级高亮） |
| 清空复原 | `clearSearch()` 把折叠状态复位到 `defaultExpandedIds`（默认 0 层 = 全折叠） |
| 命中太多时 | 命中数 > 8 时退回"逐条跳"（只铺当前那条链），避免搜"公司"摊开十几条 |

### 3. 改到的文件

* `lib/partnerTree.js`：新增 `matchPartnerLeaves()`（档案级匹配）、
  `buildVisibleRows(..., { leafHits })`（把"有档案命中的分类"并进可见性与展开逻辑）；
  返回值多了 `categoryHitIds / leafHitIds`。
* `components/partner-tree/PartnerTree.jsx`：接档案匹配、叶子只渲染命中项、
  命中行高亮 + 联系人补充显示、命中条分开计数、`clearSearch()`。
* `components/product-category/ProductCategoryTree.jsx`：**新增搜索框**、分类/商品双向匹配、
  命中分类默认展开并高亮、`N 个商品命中` 角标、清空复原。
* `App.jsx`：商品树传入 `products`（搜索要用商品名/SKU）。
* 样式：`partner-tree.css`（`.ptree__leaf.is-hit` / `.ptree__leaf-meta` / `.ptree__hits-leaf`）、
  `styles.css`（`.cat-search*` / `.cat-node.is-hit` / `.cat-mark` / `.cat-hit-note`）。

> 商品归类的两种历史形态（`category_id` 新的、`category` 名称旧的）**都要认**，
> 否则老商品搜不出来 —— 这是商品的特殊处，客户/供应商只有 `category_id`。

## 四、已知边界

* 搜索按**子串**匹配，不做拼音/首字母（"zg" 搜不到"中国"）。需要的话下一步加一层拼音索引。
* 商品树的命中只到**分类**这一级（商品不在树里渲染），命中分类会标"N 个商品命中"；
  右侧列表要不要跟着过滤，留给页面自己的搜索框（不动既有过滤逻辑）。
* 命中数 > 8 时退回逐条跳（↑↓/Enter），一次只铺一条链 —— 这是 2026-10-19 就定下的规则，
  这次只是把"档案命中"也纳入同一个计数。
