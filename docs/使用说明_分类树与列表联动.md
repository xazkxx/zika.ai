# 使用说明：左侧分类树 ↔ 右侧列表联动

> 涉及页面：客户档案、供应商档案、商品档案、仓库档案、员工档案（五页全部完成）
> 更新：2026-10-19（右侧不再默认加载全部数据）

---

## 一、这次的改变，一句话说完

**以前**：一打开页面，右边就把全部档案倒出来，左边那棵树形同虚设。
**现在**：左边是"入口"，先点一下，右边才给数据。

---

## 二、怎么用（三段就够）

### 1. 进页面时：右边是空的

你会看到一句提示：**「请在左侧选择一个分类」**。

这不是没数据、也不是加载失败 —— 是**还没选**。左侧树里所有分组也默认收起来了，
只露出一级目录（比如"集团客户""零售客户"），页面因此干净了很多。

### 2. 点一下才看数据

| 你点的地方 | 右边显示什么 |
|---|---|
| **全部客户 / 全部供应商 / 全部商品** | 这类档案的全部记录 |
| **未分类** | 还没归类的那些（往往是建档时漏填的，正好一次性捞出来补） |
| **某个具体分类** | 这个分类**以及它下面所有子分类**里的记录 |

> 点完再看标题栏：会写「集团客户 / 华北分公司 · 12 / 33 位」——
> 前面是当前分类路径，后面是"筛出来的 / 总共的"。

### 3. 想收回去：再点一次同一个分类

或者直接点「全部」，回到看全量。

---

## 三、树怎么展开

- 默认**全部折叠**，只露一级目录（按需求，避免一屏几十行看不过来）；
- 点行首的小三角 ▾ 展开这一层，再点一次收起；
- 树顶部有「展开全部 / 折叠全部」两个快捷按钮（客户、供应商的分类树里）。

---

## 四、搜索时为什么只展开一条路径

搜索框在树的顶部。输入关键词后：

- 顶部会显示「**找到 N 个**」，右边有 ↑ ↓ 两个按钮；
- 树里**只展开当前这一条**路径（命中项 + 它的父级），
  不会把你搜到的十几个结果一次性全摊开 —— 那正是以前"搜一下满屏都是、认不清"的原因；
- 按 **Enter**（或点 ↓）跳到下一个命中，树会跟着换到那一条路径；
- 命中的文字片段会高亮成黄色；按 **Esc** 清空搜索，树**回到你原来的折叠状态**（不会一搜就全开）。

## 五、几个常见疑问

**问：右侧一直是空的，是不是坏了？**

先看左侧有没有高亮行。没有高亮 = 还没选，点一下「全部」即可。
如果点了「全部」还是空，再看右侧标题的「0 / 33 位」——
分母不是 0 就说明档案在、只是被搜索词筛掉了，清空搜索框试试。

**问：我选了一个分类，但列表里出现了不属于它的商品？**

分类是**按名称/编号归属**匹配的（同一分支重名时会宽松匹配），
所以理论上会多带，不会漏。真发现挂错，去商品编辑里把类别改对即可。

**问：左侧数字（角标）为什么和右边条数不一样？**

角标是"这个分类一共有多少条"，**不受搜索词影响**——
这样你边打字边看左边，数字不会跳来跳去。右边是"当前筛出来的"。

## 六、仓库 / 员工两页也改完了

这两页以前**没有左侧树**（一张大表格，左半屏空着），现在按同一套手感重做：

| | 左侧树按什么分 | 为什么这么分 |
|---|---|---|
| **仓库档案** | 全部仓库 → **启用 / 停用** | 仓库没有层级、也没有分类，硬造"地区/类型"就是造假数据；但停用仓不能和可用仓混在一起找 |
| **员工档案** | 全部员工 → **部门层级**（可逐级展开） | 部门在后端本来就是树（`department.level`），是真实维度，不是编的 |

两点差异要知道：

1. **员工页进页面时不请求数据**，点「全部员工」或某个部门才拉一次；
   之后切部门只做本地过滤，**切换是瞬间的**（不会闪一下旧数据）。
2. **仓库列表仍会在进页面时加载** —— 因为开单页的"仓库"下拉也用这份数据，
   不能按页面延迟请求；但**表格显示**已经按需求门控了（未选中就是空表）。

员工页还有个「未分配部门（N）」入口，专门捞"建档时忘填部门"的人 ——
以前这个筛选条件藏在部门下拉里，基本上没人会想起来用。
