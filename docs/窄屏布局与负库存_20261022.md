## 问题 1：窄屏双栏塌成单列

### 真相（两层，缺一不可）

`resizableLayout.css` 在窗口 ≤1080px 时做了两件事：

```css
@media (max-width: 1080px) {
  .management-grid.mgrid--split { grid-template-columns: 1fr; }  /* ① 三列变一列 */
  .mgrid-handle { display: none; }                                /* ② 手柄隐藏 */
}
```

① 让左树和右表**上下摞在一起**，看着就是"表格掉到中间"。
② 更阴：手柄一 `display:none` 就脱离网格流，浏览器**自动排布**把右栏卡片塞进第 2 列
（也就是 12px 的手柄轨），第 3 列空着 —— 表格被挤成一条缝，右边一大片空白。
这就是截图里"左侧极窄、表格挤在中间"的真实成因。

### 改法（`styles.css`，覆盖组件 CSS）

```css
@media (max-width: 1080px) {
  .management-grid.mgrid--split {
    grid-template-columns: clamp(200px, 32%, 300px) 12px minmax(320px, 1fr);
    gap: 0;
    overflow-x: auto;          /* 再窄就整体横向滚动，别继续压 */
  }
  /* 手柄必须留着占位 */
  .management-grid.mgrid--split > .mgrid-handle { display: block; }
}
```

双类选择器（0,2,0）压过 `.management-grid`（0,1,0），与打包顺序无关。
客户/供应商/商品/库存四个双栏页面同时受益 —— 它们共用同一套 `mgrid--split`。

## 问题 2：商品页"未选类别却全量"

`filterProductsByCategory(products, cats, null)` 的语义是**不过滤=全量**，
所以一进商品页就是 262 行，而客户页是"空表 + 请选择分类"，两边完全两种体验。

```js
const tableRows = productTableRows === null
  ? (picked ? filteredProducts : [])   // ← 没选类别就不出数据
  : productTableRows;                  // 智能创建/选品流程显式传入的结果照旧尊重
```

行高方面：`ErpTable` 的单元格是 `padding` 撑高、没有写死 `height`；
这次的"截断"其实来自窄卡片下 7 列互相挤。现存量表给了 `min-width: 680px`
（宁可横向滚动，也不把商品名压成省略号），并把负库存徽标做成紧凑的 ⚠ 图标。

## 问题 3：库存总量 −24,760

### 这不是算错，是"只有出库、没有入库"

逐商品核对流水（`inbound − outbound`）：

| SKU | 商品 | 入库 | 出库 | 净 |
|---|---|---|---|---|
| 0109 | 劳保手套 | 0 | 24,160 | **−24,160** |
| 0186 | 编织袋 | 0 | 6,000 | −6,000 |
| 0066 | 纱线手套 | 0 | 3,828 | −3,828 |

共 **104 个商品为负、合计 −51,344**（按仓库×商品展开后行数更多）。
负数全部来自**历史导入的销售出库单**：那批数据只导了出库流水，
没有对应的采购入库或期初库存 —— 账上确实是"卖出去的比买进来的多"。

### 界面改法（不再把负数混进总量）

| KPI | 旧 | 新 |
|---|---|---|
| 在库合计 | 库存总量 = **−24,760**（把所有行直接相加） | **26,585**（只累加正数） |
| 负库存商品 | 无 | **110**（合计 −51,345，红字） |
| 库存金额 | ¥**−1,464,576**（负数×单价） | ¥**281,751.58**（只算正库存） |

另外：

- 负库存行**整行淡红底 + 数量红字**，数字后面跟一个 ⚠ 徽标（悬停解释原因）；
- 表头上方一条红框说明条，直接写清"只有出库流水、没有采购入库或期初库存"，
  并指路「基础资料 → 商品期初库存」补录；
- 补录完成后数字会自动转正，不需要改代码。

> 底层汇总 `summary.total_quantity` 仍在（后端没改，避免让你重启服务），
> 但**界面不再使用它**，而是在前端按 `rows` 重新拆口径。要彻底清理，可在
> 期初库存页按盘点数补录，或补采购入库单。

## 问题 4（顺带）：库存流水点不开

流水表原来只有 5 列干数据，产品列显示的甚至是 `product_id`，点不动、看不到来源单。

现在：

- 产品列显示**商品名**（用商品档案建映射）；
- 新增「时间」列；入库/出库用不同颜色标签；
- **点任意一行 → 右侧详情抽屉**：商品、数量（带正负号）、单价、来源单号、关联类型、
  发生时间、备注，并把「要更正数量该怎么做」写在抽屉里（走单据反审核/改单，别直接改流水）。

> 为什么不做"直接改流水"：流水是账的真相源，改了会和单据对不上，
> 等于把"可追溯"这条底线拆掉。需要改数量请回单据侧处理。
