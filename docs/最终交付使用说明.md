## 二、双击就能用（桌面版）

1. 找到交付文件夹，双击 **`ERP管理系统.exe`**
   （整个 `ERP管理系统` 文件夹一起拷走，**不能只拷 exe**）
2. 程序在后台启动（没有黑窗口），几秒后**自动打开浏览器**到 `http://127.0.0.1:8010`
3. 没有自动打开 → 手动访问 `http://127.0.0.1:8010`
4. 登录：账号 `admin` + 交付时给你的密码

### 关闭

它是后台进程，没有窗口可关：

```bat
taskkill /F /IM "ERP管理系统.exe"
```

### 出问题先看这三个

| 现象 | 处理 |
|---|---|
| 打开是白屏 | `Ctrl + Shift + R` 强制刷新（新版本换了 JS 文件名，旧缓存会白屏） |
| 提示端口被占用 | 说明已经在跑了，直接用现有窗口；要重启先按上面的命令结束进程 |
| 双击毫无反应 | 看 exe 同目录的 `erp_error.log`，里面写着失败原因 |

### 附件目录（重要）

合同/发票/客户归档的原件放在 **exe 旁边的 `data` 文件夹**，不在程序里。
换电脑、换目录部署时，**必须把整个 `data` 文件夹一起搬过去**
（库里存的是相对路径，搬过去就能认回）：

```bat
robocopy "data" "dist\ERP管理系统\data" /E
```

## 三、以后开新单的流程（模板已就位）

### 1. 建档案（只需一次）

- 客户档案：编码可留空自动生成；**分类可以拖**——左侧分类树 + 右侧列表，直接拖行归档
- 商品档案：类别从类别树里选；单位/换算关系在弹窗里维护
- 供应商档案 / 仓库：按需

### 2. 销售开单（日常主流程）

```
销售管理 → 开单管理 → 新增
  ① 选客户（输名字直接搜索）
  ② 选仓库
  ③ 加商品行：数量 / 单价 / 单位（单位换算自动按档案里的系数）
  ④ 保存 = 草稿（可改可删，不动账）
  ⑤ 审核 = 真正出库并生成应收
```

**单据规则（封版口径，别绕）**：

| 想做的事 | 正确做法 |
|---|---|
| 草稿改内容 | 直接改，账一分不动 |
| 已审核要改 | 先「反审核」退回草稿 → 改 → 再审核（账随单动） |
| 单据作废 | 走系统里的「作废」，不要手删流水 |
| 完结单据 | 必须**钱票两清**（无欠款 + 已开票），否则提示 `not_settled` |

### 3. 收款与开票

- 收款：财务管理 → 收支登记（关联单据，账户余额自动跟着走）
- 开票：发票管理 → 关联到具体出库单（完结闸会检查这个）

### 4. 对账与报表

报表分析 → 往来对账 / 销售对账单 / 经营分析。历史导入的单据在备注里带
`历史导入|源单号=…`，按客户取数即可（一封对账单可能拆成 2~3 张系统单，这是正常的）。

### 5. 新模板在哪

历史导入用的是**对账单模板**，不是以后的录单模板。
以后开单走系统的「开单管理」界面（或用 `artifacts/shansong_import/模板_历史销售单导入模板.xlsx`
做批量导入，导入后仍需在系统里审核）。

## 四、常见问答

**Q：为什么左侧树里客户名字下面还有一层？**
分类下平铺的客户就是"文件"，子分类是"文件夹"——跟资源管理器一样。展开一个一级分类时，
同级的其它分类会自动收起（手风琴），屏幕不会糊成一片。

**Q：表格列太窄/太宽？**
表头之间有淡灰分隔线，鼠标移上去变蓝 → 拖。宽度自动记住；双击分隔线恢复默认。

**Q：拖拽后左侧没跳过去？**
目标本来就可见时不会滚动（没东西可滚），但会**蓝框呼吸 1.6 秒**并展开祖先。

**Q：数据备份在哪？**
`backup\` 目录，每天 21:37 自动整库 dump，保留 14 份。手工备份：

```bat
E:\AI\Postgres\bin\pg_dump.exe -h 127.0.0.1 -U erp -d erp -Fc -f backup\手动_日期.dump
```

**Q：怎么升级到下一版？**
换掉 `dist\ERP管理系统\` 整个文件夹（保留里面的 `data`），然后浏览器 `Ctrl + Shift + R`。
版本号看左下角，不是 `v153` 就说明还在用旧缓存。

### 这一版修了什么（都会影响你日常用到的数字）

1. **对账单「本期已开票」恒为 ¥0**（严重）
   对账单方向是 `out/in`，发票方向是 `output/input`，比较永远不成立
   → 任何客户的对账单都显示"没开票"，期末应收被算成负数（看着像客户多付钱）。
   已修，并加了回归测试，现在全额开票 + 全额收款 → 期末应收 = 0。
2. **自己开的发票进不了对账单**
   原来只认历史导入票的 `counterparty_name`；App 里新建的票只有 `customer_id`。
   现在两套都认（含 `buyer_name` 兜底）。
3. **测试数据清理链漏洞**
   测试产生的发票 / 对账单以前不会被清（曾在库里留下 58 张发票、27 张对账单）。
   已补进 `clean_test_data.py`，跑完测试自动归零；`clean_e2e_data.py` 也修了
   "期初不是独立表"和"孤儿流水不校验"两个问题。

详细过程与证据见 `docs/全流程业务闭环自测报告_20261022.md`。

> ⚠️ 还有一项**等你拍板**：没有合同的客户，对账单上「剩余未收」会显示成负数
> （公式是 `合同额 − 已收`，合同额为 0 时就是 `−已收`）。
> 期末应收那列是对的，只是这一列看着别扭。改法有三种，报告第六节列了，你选一个我就改。
