# 测试库隔离（2026-10-27 · A5）

**一句话**：`tests/` 里 608 个测试从「直连生产库 `erp`、跑完按名字擦数据」改成「**只连
`TEST_DATABASE_URL`，没配就整场拒绝运行**」，配套用独立 PostgreSQL 实例（端口 55432）
做测试库，生产实例（5432）在这条链路里根本连不上。

---

## 一、之前是什么样（为什么必须拆）

- `tests/conftest.py`（原 37 行）只做一件事：整场测试跑完，调 `scripts/clean_test_data.py`
  按测试脚本里写死的名称删残留。
- 测试用的是 `.env` 里的 `DATABASE_URL` —— 也就是**正式库 `erp`**。测试会真实建商品、
  客户、供应商、仓库，会走审核 / 状态机 / 期初 / 日志清空这类全库接口。
- 两个后果：
  1. **擦不干净就污染业务数据**。商品总数突破接口默认分页上限 500、分页断言变不稳，
     就是这么累积出来的；
  2. **写错一行就是生产事故**。测试里一个 `DELETE` 少个 `WHERE`、一个「清空期初」接口
     调错参数，直接删的是用户的钱账。`tests/prod_snapshot.py` 那套快照工具就是为了
     兜这类事故才写的 —— 需要兜，说明结构本身不安全。

## 二、现在怎么拦（三道闸，任何一道不过就退出码 2、一个测试都不跑）

1. **没有 `TEST_DATABASE_URL`** → `pytest.exit`，并打印当前 `DATABASE_URL` 和起库命令；
2. **`TEST_DATABASE_URL` 没写库名** → 同样中止（防 `postgresql://user@host` 这种半截串）；
3. **`TEST_DATABASE_URL` 与 `DATABASE_URL` 的 host/port/db 三者相同** → 中止。
   —— 这条是核心：即使有人把测试库配成生产库，也跑不起来。

通过之后，`conftest` 在 **`pytest_sessionstart`**（早于任何测试模块 import、因此早于
`app.core.config.settings` 被读）把 `os.environ['DATABASE_URL']` 改写成测试库连接串。
`pydantic-settings` 里环境变量优先级高于 `.env`，所以**应用代码一行都没改**，测试整体
落到测试库上；`scripts/db_config.py`、`clean_test_data.py` 也跟着走测试库。

> 为什么闸门放在 `pytest_sessionstart` 而不是 conftest 模块顶层：顶层抛 `pytest.exit`
> 会被 pytest 包成 `ImportError while loading conftest`，红字一大片、看不出人话。

## 三、测试库怎么来（`scripts/test_db.py`）

不在 5432 实例里建 `erp_test`，原因是**权限**：连库账号 `erp` 的 `rolcreatedb = false`，
建库要超级用户密码，而密码不该进仓库、也不该让每个人去问。

脚本改用 PostgreSQL 自带 `initdb` 另起一个**本地实例**：

| 项 | 值 |
| --- | --- |
| 数据目录 | `<项目根>/.pgtest`（已加 `.gitignore`） |
| 端口 | 55432（可用 `ERP_TEST_PG_PORT` 改） |
| 超级用户 / 库 | `erp_test` / `erp_test` |
| 认证 | `trust`，只监听 `127.0.0.1`（**仅本机开发**，别暴露到网络） |
| 初始数据 | A1 备份 `backup/pre_optimize_20261027/db_pre_optimize.dump` |

```powershell
python scripts\test_db.py init      # 首次：initdb + 起服务 + 建库 + 灌 dump + 写 .env
python scripts\test_db.py start     # 每次开机后
python -m pytest                    # 直接跑，conftest 用 TEST_DATABASE_URL
python scripts\test_db.py reset     # 测试数据乱了：清库重灌
python scripts\test_db.py status    # 看状态 / 当前 TEST_DATABASE_URL
```

`init` 会往 `.env` 追加一行 `TEST_DATABASE_URL=postgresql+psycopg://erp_test@127.0.0.1:55432/erp_test`
（`.env` 不入库；已有同名键则不动）。`.env.example` 已同步补上这一项。

## 四、验收证据（2026-10-27 实测）

1. **没配 TEST_DATABASE_URL 时拒绝运行**：`pytest -q` → 打印
   `[conftest] 拒绝运行：没有配置 TEST_DATABASE_URL。` 并中止，0 个测试执行。
2. **测试库结构与生产库一致**：`public` 66 表、`co_02` 56 表、`co_03` 56 表（两边同数）。
3. **全量测试**：`608 passed in 197.35s (0:03:17)`，退出码 0；
   输出首行是 `[conftest] 测试库：erp_test@127.0.0.1:55432/erp_test` 与
   `[conftest] 生产库：erp@127.0.0.1:5432/erp —— 本场测试不会连接它`。
4. **「真的没碰生产库」的实证**：跑 `tests/test_crud.py`（4 个测试）前后读
   `pg_stat_database.xact_commit`：

   | 库 | 事务数变化 |
   | --- | --- |
   | 生产 `erp`（5432） | 1003020 → 1003022（**+2**，只有监控连接自己） |
   | 测试 `erp_test`（55432） | 19605 → 20089（**+484**，测试真的在这里跑） |

## 五、回滚

```powershell
git revert <A5 commit>                 # 代码层：conftest 恢复成只做清理
python scripts\test_db.py stop         # 停掉测试实例（不影响生产 5432）
```

## 六、注意事项

- **新机器**：先 `python scripts\test_db.py init` 再跑测试；漏了会被闸门挡住并给出命令。
- **团队共享测试库**：可以直接把 `TEST_DATABASE_URL` 指向远端库，conftest 会放行但打印
  「测试库在远端主机 …，确认那是测试库而不是生产库」的告警。
- **trust 认证**只适合本机开发。要把这个实例开放给局域网，先改成 `scram-sha-256` 并配密码。
- `prod_snapshot.py` 的类名（`ProdSnapshot`）是历史命名，保留不动；它现在是「全库范围
  操作的保险绳」，跑在测试库上 —— 但坏习惯不值得养成，新测试仍不要依赖它兜底。
