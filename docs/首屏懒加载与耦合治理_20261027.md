## B4 首屏瘦身：47 个页面改路由级懒加载

**改动**（`frontend/src/App.jsx` 一个文件）：

```jsx
// 前：47 条静态 import，全部打进 index-*.js
import OverviewPage from './pages/OverviewPage';

// 后：
const OverviewPage = lazy(() => import('./pages/OverviewPage'));
const pageLoadingFallback = <section className="panel">页面加载中…</section>;

{selectedTab === 'overview' && <PageBoundary><OverviewPage ctx={appCtx} /></PageBoundary>}
```

- `PageBoundary` = **错误边界 + Suspense 合一**，一个页签只多一层标签：
  - Suspense 的 fallback 只占内容区，不包侧边栏/顶部/弹窗 → chunk 未到位时不会整屏白；
  - 错误边界兜住「chunk 404」——发版后 chunk hash 全变，用户手上那份 index.html 可能是旧的
    （SW 缓存 / 没整页刷新），点进某页签会请求一个已被清掉的文件。**没有边界时 React 卸载整棵树 = 白屏**；
    有边界则只坏这一页，给一句人话 + 「刷新页面」按钮。这不是可选项，是懒加载的配套件。
  - 顺带也兜住「某页自己 render 抛异常」（以前同样是整站白）。
- `pageLoadingFallback` 是同一个不可变 React 元素，47 个边界复用安全。
- 沿用仓库已有写法（`ContractsLedger`/`StatementEditor` 早就这么做了）。

**体积（`npm run build` 实测，vite 口径）**

| 指标 | 改造前 | 改造后 | 变化 |
| --- | --- | --- | --- |
| `index-*.js` | 2 579 KB | **1 435 KB** | **−44%** |
| `index-*.js` gzip | 667 KB | **469 KB** | **−30%（−198 KB）** |
| 入口 CSS | 198 KB（单文件） | **135 KB** | 同步拆分 |
| 产物文件数 | 11 | 78 | 47 页各自成 chunk |

## B4b 重型依赖按需加载：xlsx / pdfjs / tesseract（已完成）

**做法**

新增 `frontend/src/lib/lazyLibs.js`：`loadXLSX()` / `loadPdfjs()` / `loadTesseract()` 三个函数，
内部 `await import()` + promise 缓存（同一个库不会下两遍）+ 失败清缓存（断网/发版后 chunk 404
是一次性故障，不能让用户"刷新一次仍然永远失败"）+ CJS 导出拆包。调用点都是 async：

| 位置 | 原来 | 现在 |
| --- | --- | --- |
| `App.jsx` `exportInvoiceDetailExcel` | 静态 `import * as XLSX` | `await loadXLSX()`；失败 `setNotice` 后返回 |
| `App.jsx` `exportInvoiceReportXlsx` | 同上 | 同上 |
| `App.jsx` `readPdfInvoiceText` | 静态 `import * as pdfjsLib` + 模块顶层设 worker | `await loadPdfjs()`（worker 路径搬进 loader） |
| `App.jsx` `readImageInvoiceText` | 静态 `import Tesseract` | `await loadTesseract()`（外层已有 try/catch） |
| `PartnersBoard.jsx` `runExport` | 静态 `import * as xlsx` | `await loadXLSX()`；失败 `alert` 后返回 |

**体积（`npm run build` 实测）**

| 产物 | B4 之后 | B4b 之后 | 变化 |
| --- | --- | --- | --- |
| `index-*.js`（首屏） | 1435 KB / gzip 469 KB | **638.78 KB / gzip 211.26 KB** | **−796 KB / gzip −55%** |
| `xlsx-*.js`（点导出才下） | 含在主包 | 429 KB / gzip 143 KB | 独立 chunk |
| `pdf-*.js`（解析 PDF 才下） | 含在主包 | 365 KB / gzip 108 KB | 独立 chunk |
| `index-BlzDtei6.js`（tesseract，文件名沿用入口名） | 含在主包 | 16 KB / gzip 6 KB | 独立 chunk |
| `pdf.worker.min-*.mjs` | 已独立 | 1343 KB / gzip 392 KB | 只在解析 PDF 时下载 |

主包 gzip：**667 → 469 → 211 KB（相对优化前 −68%）**；产物 81 个文件，总体积 4325 KB。

**验证**

1. `node ../scripts/check_undefined_refs.cjs` → 0（144 文件，**作用域级**检查；门禁串在 `npm run build` 前面）；
2. 主包里已无这三个库：`tesseract.js` 字样 0 次；worker 路径被固化成 `/assets/pdf.worker.min-*.mjs`；
3. 动态 `import()` 调用点 = 3 处重型库 + 47 个页面 chunk（共 50 条），逐个可在产物里对上；
4. 浏览器实测（headless Chrome + 静态服务器，真的 `import()` 这三个 chunk）：
   - `xlsx` → OK，`utils` 可用；
   - `pdf` → OK，`getDocument` 可用；
   - tesseract chunk → OK，`recognize` 可用；
   - `pdf.worker.min-*.mjs` → HTTP 200 / `text/javascript`。

**踩到的坑（写下来省下一次）**

- `pdfjsLib.GlobalWorkerOptions.workerSrc` 原来写在 `App.jsx` **模块顶层** —— 为了设一个静态属性，
  把 640 KB 的 pdfjs 拉进首屏。搬进 `loadPdfjs()` 后必须**拿到库之后再设**：`new URL(..., import.meta.url)`
  是相对「执行这段代码的模块」解析的，位置换了路径也得跟着换。
- `import('tesseract.js')` 返回的命名空间被 rollup 压成了短名（产物里是 `export{pt as i}`，消费端是
  `import(...).then(t => t.i)`）。所以 `loadTesseract()` 里保留 `mod.default.recognize ? mod.default : mod`
  双重拆包 —— 只看 `.default` 会拿到 `undefined`，OCR 会静默变成「识别不出内容」。
- **最贵的一个坑（2026-10-27 白屏事故）**：静态 import 删了，`appCtx` 里的
  `Tesseract,` / `XLSX,` / `pdfjsLib,` 三个**对象简写属性**忘了删。简写属性是**引用**不是键名，
  对象字面量在 render 期间求值 → `ReferenceError: Tesseract is not defined` → **整屏白**。
  更糟的是旧门禁没报：它按「这个文件里某处出现过同名定义」判断，而 `readImageInvoiceText` 里
  正好有局部 `const Tesseract = await loadTesseract()`，把顶层漏掉的键**洗白**了。
  修法两条：① 三个库一律**不进 appCtx**（页面要用自己 `await loadXxx()`）；
  ② 门禁 `check_undefined_refs.cjs` 改用 `@babel/traverse` 的**作用域级** `scope.hasBinding`
  （函数内局部变量不再给顶层背书），并保留简写属性/数组裸标识符两类检测。
  回归自测：造一个「函数内局部同名 + 顶层简写引用」的样本文件，新门禁报 2 处、旧门禁 0 处。

## B5 发票 Excel 导出搬到后端（Office 兼容热修，2026-10-26）

**现象**：导出的 `.xlsx` 有内容（不是 0 字节），**WPS 能正常打开，Microsoft Office 提示「文件已损坏」**。

**根因（不是 B4b 懒加载）**：
- 懒加载只决定"引擎能不能加载到"，不会改写 XML。把前端导出逻辑原样在 Node 里复现，
  产物 zip 结构、`[Content_Types].xml` 全覆盖、所有 XML 都能严格解析 —— 包本身"合法"。
- 真正的坑在 SheetJS CE 的单元格写法：**普通文本被写成 `t="str"`**。那是 ECMA-376 里的
  **公式字符串**（公式缓存值），值靠 inline `<v>` 承载，包里也没有 `xl/sharedStrings.xml`。
  WPS 一路容错；Office 的 OPC 校验严格，遇到这种"合法但不主流"的写法直接判损坏。
  复现证据：`<c r="A2" t="str"><v>A4纸_x000b_垂直制表</v></c>`。
- 顺带否掉两个猜测：SheetJS 会把控制字符转义成 `_x000b_`（不是脏 XML），
  超 32767 字符会**抛错**（不是静默写坏）；开发库里发票文本也没有控制字符。

**修法：发票 Excel 一律后端生成，`openpyxl` 直出标准 xlsx。**
- 新模块 `app/services/invoice_export.py`：`ledger`（发票清单 + 发票明细）/ `report`（发票报表）两种布局；
  表头深蓝白字、**冻结首行 + 自动筛选**；金额/数量是**数字**（`#,##0.00`，财务能整列 SUM）；
  文本先洗 XML 非法控制字符并截断到 32767（openpyxl 遇到脏字符会直接抛 `IllegalCharacterError`）。
- 新接口 `GET /api/v1/invoices/export/xlsx?layout=ledger|report&ids=1,2,3`，与原件/二维码导出同一条双通道：
  `Accept: application/json` → base64 JSON，否则二进制（给 curl / 外部脚本）。
  排序口径与界面一致：开票日期升序（空日期排最后）、同日按 id。
- 前端 `exportInvoiceDetailExcel` / `exportInvoiceReportXlsx` 只负责把字节存成文件
  （走 `downloadBase64File` 的 base64 通道，避开浏览器接管二进制响应），**App.jsx 不再 import xlsx**。
- 往来单位导出（PartnersBoard）还在用前端引擎，但改成 `writeFile(..., { bookSST: true })`：
  字符串进 `xl/sharedStrings.xml`、单元格用 `t="s"`，即 Excel 原生写法（默认的 `t="str"` 就是上面那个坑）。

**回归测试** `tests/test_invoice_excel_export.py`（6 项）钉住：OPC 完整（必备 part + 每个 part 有 content type +
全部 XML 严格可解析）、**产物里不许再出现 `t="str"`**、金额是数字、脏文本不炸，以及只导勾选项 / 400 与 404 要说人话。

**验证**：全量 `614 passed`；起真服务用库里 4 张发票实跑两种布局 —— `sharedStrings=False`、`no-t-str=True`、
`dims=A1:O5`、`freeze=A2`、`filter=A1:O5`；主包 gzip 211.24 → **210.49 KB**（发票导出不再拉 429 KB 的 xlsx chunk）。
