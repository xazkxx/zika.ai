# 商品分类树：箭头 / 拖拽 / 与客户树对齐（2026-10-22 · 第四轮）

> **版本 v166 · 20261022-1314**（PWA `erp-pwa-v166`），纯前端。
> 三个问题同源：**商品树从没接过 `onMove`，而且 `collapsed` 的语义写反了**。

---

## 问题 2 先说（更根子）：手柄消失 = `onMove` 没传

`ProductCategoryTree` 里有这样一句：

```js
const canDrag = typeof onMove === 'function';
```

`onMove` 为空 → `canDrag = false` → **手柄不渲染、整行也拖不动**。
而 `App.jsx` 的 `renderCategoryNodes()` 只传了 `nodes / value / onChange / counts / busy /
onAddChild / onEdit / onDelete`，**唯独没传 `onMove`** —— 客户树传了（`onMove={cats.move}`），
商品树漏了。这就是"客户树修好了、商品树又退化"的直接原因：两套接线，一套漏了一根。

### 还有一个埋着的地雷

`moveCategory`（商品）打的是 `POST /product-categories/{id}/move` ——
**这个路由后端根本不存在**（只有 GET / POST / PATCH / DELETE）。
所以一旦把手柄接上，拖一下就 404。这次一并改成用现成的
`PATCH /product-categories/{id}`：先改 `parent_id`，再按目标父级重排 `sort_order`
（拖拽给的是 `beforeId` 语义，接口没有，就在前端排好序号逐条写）。

## 问题 1：箭头"不见了" —— 它其实在，但小到看不见

实测 DOM：`办公用品`（id=6）的箭头**存在**，`<svg width="8">`、颜色 `#94a3b8`、
盒子 16px。8px 的浅灰小三角在 300px 的窄栏里，确实很容易被当成"没有箭头"。

改法：

| 项 | 改前 | 改后 |
|---|---|---|
| 图标尺寸 | 8×8 | **10×10** |
| 颜色 | `#94a3b8`（很浅） | `#64748b` |
| 悬停 | 无反馈 | 圆形淡蓝底 + 变主色，光标 `pointer` |
| 容器 | 14px 无对齐 | 16×16 居中 flex |

> 顺带确认：`children` 是后端 `GET /product-categories` 真的嵌套返回的（办公用品 → 办公家具），
> 不是前端拼的；箭头条件 `hasChildren = node.children.length > 0` 一直是对的。

## 问题 3：对齐客户树（手风琴）

给商品树补上同级手风琴。这里踩了个很典型的坑：

```js
// collapsed 是「折叠名单」：在名单里 = 当前折叠着 = 这次点击要展开
if (prev.includes(id)) { /* ← 这个分支是"展开"，手风琴必须写在这里 */ }
```

第一版把 `prev.includes(id)` 当成"收起"、手风琴写在 else 分支 ——
结果点开兄弟时，走的正是"展开"分支直接 return，**谁也不折叠**。
现在：展开 = 把自己从折叠名单删掉 + 把同父级兄弟加进去；收起 = 加回名单。
