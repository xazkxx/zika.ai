# 拖拽联动 / 行内编辑 / 换文件夹感（2026-10-22）

> 三件事：① 拖完右侧必须立刻出数据；② 行内双击编辑，且落点判断要准；③ 切分类要有"换文件夹"的利落感。
> 版本 **v160 · 20261022-1130**（PWA `erp-pwa-v160`），纯前端。

---

## 问题 1：拖完右侧空着，点分类也不加载

### 真正的原因

`handlePartnerDrop` 里那句被条件包住了：

```js
if (treeMode === 'category') setCategoryId(target)   // ← 旧代码
```

只要用户当时停在「按分组」视图，**右表就一个字都不动**，停在初始的"请先选择一个分类"空态。
左侧树那边照样展开、闪烁、提示成功 —— 于是看起来"提示成功了但右边是空的"。

### 改法

```js
if (treeMode !== 'category') setTreeMode('category');  // 无条件切回分类视图
setCategoryId(targetId === null ? UNCLASSIFIED : targetId);
```

同时把空态文案拆成两句（这两件事以前共用一句，误导性极强）：

| 场景 | 文案 |
|---|---|
| 还没选分类 | 请先在左侧选择一个分类（带指引） |
| **选了分类但这一类确实没档案** | 「这个分类下还没有客户」+ 按钮「查看全部」 |

有了后者，即便真的空，用户也不会误判成"拖拽没生效"。

## 问题 2：落点判断偏了（拖进 A、提示 B）

### 原因

`onDrop` 回传的是**这一行闭包里的 targetId**。浏览器只要把 drop 派给了另一行
（树的滚动重排、吸附表头挡一下、祖先展开导致行位移），提示和实际落库就会错位 ——
而旧验收用 `new DragEvent()` 直接 dispatch 到节点上，**绕过了命中测试**，所以一直"绿"。

### 改法

```js
// 以"松手坐标下真正那一行"为准，命不中才退回闭包值
const under = document.elementFromPoint(event.clientX, event.clientY);
const rowEl = under && under.closest('[data-node-id]');
```

- 被拖的 id 也改从 `dataTransfer` 读（`dragend` 与 `drop` 的先后各浏览器不一致，
  万一 `dragend` 先把 ref 清了，页面还能拿到真实列表）；
- 提示语改用**树回传的节点名**（用户眼前那一行），服务端名字只在"两者不一致"时补一句
  —— 这种偏差必须能一眼看出来，而不是被一句"成功"盖过去。

### 验收方式的修正

`scripts/verify_partner_linking.cjs` 改用 Puppeteer 的 **drag interception** 做真实拖拽，
并断言"提示里的分类名 == 目标分类名 == 落库 category_id"。

## 问题 3：行内编辑（客户 / 供应商 / 商品）

- **双击格子**直接变成输入框；`Enter` 保存、`Esc` 取消、点别处自动保存。
- 可编辑列：客户/供应商 `名称 / 电话 / 邮箱 / 地址 / 级别 / 业务员`；商品 `名称 / 规格 / 单位`。
  **编码与分类不开放**（编码是主键、分类走拖拽/弹窗），避免误改影响单据归属。
- 落库只 PATCH 改过的那一个字段（后端 `exclude_unset` 语义），不会覆盖别人正在改的列。
- 行依然 `draggable`，编辑与拖拽互不打架。

### 三个坑（都写在代码注释里）

| 坑 | 现象 | 解法 |
|---|---|---|
| `pointerdown` 上的 `preventDefault` | 双击永远不触发 | 不在 pointerdown 上禁默认 |
| `PointerEvent.detail` 恒为 0 | 拿它判双击必失败 | 自己数 400ms 内第二次按下 / 用 dblclick |
| 输入框挂载瞬间的 `blur` | 输入框一闪就没 | 记录打开时刻，250ms 内的 blur 忽略 |
| 双击冒泡到行 | 草稿被重置回原值，永远改不进去 | 编辑态忽略双击；`closest('input')` 直接 return |

## 问题 4（顺手）：换文件夹的过场

切分类时给表格 140ms 淡入（`wrapClassName="is-switching"`），只淡入、**不换骨架屏**
—— 140ms 的骨架只会闪一下，比不闪更慌。
