## 三、链路实测：断在哪

### 3.1 目标链路

```
合同 contracts
   └─ 销售订单 sales_orders(doc_type='order')
        └─ 销售开单 sales_orders(doc_type='outbound')  ← 出库/结算发生在这里
             ├─ 出库 inventory_transactions(related_type='sales_out')
             ├─ 签收 signed_at / signed_by / logistics_*   ← 字段刚补，历史为空
             ├─ 发票 invoices(sales_order_id)              ← ❌ 全空
             └─ 收款 financial_transactions(related_order_id)
                  └─ 对账单 statements（汇总快照）
```

### 3.2 五个断点（按严重程度排序）

| # | 断点 | 实测证据 | 影响 |
|---|---|---|---|
| **1** | **发票挂不到业务单据** | 4 张销项发票 `customer_id`=NULL、`contract_id`=NULL、无 order 列；`counterparty_name`="陕西送变电工程有限公司"，而客户档案是"陕西送变电公司一分司-攀西特高压…"（名称不相等） | 对账单「已开票」恒为 0；三张对账单 `invoiced_amount` 实测 **0.00 / 0.00 / 0.00** |
| **2** | **合同 ↔ 订单无连线** | 2 张合同的 `order_id`、`order_no` 全 NULL；销售单也没有 `contract_id` 列 | "按合同号聚合"只能退化成"按往来单位 + 期间"猜 |
| **3** | **签收/物流无字段** | 全库无 `signed_at`/`logistics_no` 等列 | 物流流完全不可追溯，打印模板上的"客户签收"是手写空栏 |
| **4** | **订单 → 开单未连线** | 3 张销售单里 2 张 `doc_type='order'`、1 张 `'outbound'`，而该开单 `source_order_id` 为 NULL | 订单和实际出库/收款是两套东西，"这单出没出货"查不出来。注：直接开单（不经过订单）是合法业务，所以这条**不能强制**，只能提示 |
| **5** | **发票与收款各自独立** | 收款挂在 `sales_order_id` 上，发票挂不到同一单 | 无法回答"这单货已收钱、票开了没" |

### 3.3 当前"能不能 100% 聚合"

**不能。** 就现有数据：

- 按**单据号**（销售单）聚合：出库 ✅、收款 ✅、发票 ❌、签收 ❌ → 4 流只有 2 流
- 按**合同号**聚合：合同 ✅、发票 ❌（contract_id 空）、订单 ❌（无关联列）→ 基本不可用
- 按**往来单位 + 期间**聚合：能出数，但对账单里「已开票」必为 0（名称匹配失败）

第二阶段补完字段 + 手工认领 4 张发票后，按单据号聚合才能做到 **100%**。

## 五、金额精度专项（本次体检的第二个发现）

你要求"所有金额必须 Decimal 或保留两位小数"——现状是**半达标**：

| 表 | 金额列类型 | 判断 |
|---|---|---|
| `statements`（10 个金额列） | `numeric(12,2)` | ✅ 已达标 |
| `contracts.total_amount` | `numeric(12,2)` | ✅ 已达标 |
| `sales_orders`（7 个金额列） | `double precision` | ❌ 浮点 |
| `sales_order_items`（amount/unit_price） | `double precision` | ❌ 浮点 |
| `purchase_orders` / `purchase_order_items` | `double precision` | ❌ 浮点（对称问题） |
| `invoices`（3 个金额列） | `double precision` | ❌ 浮点 |
| `financial_transactions`（amount/applied_amount） | `double precision` | ❌ 浮点 |

**当前库里没有 >2 位小数的脏值（实测 0 行）**，所以迁移是"干净数据换类型"，风险可控。

**口径必须守住两条**（沿用项目既有铁律）：

- **钱**（金额/合计/税额/已收已付/欠款/余额）→ `numeric(14,2)`
- **费率**（单价/数量）→ `numeric(14,4)`，**且不截断**
  （`73.901 × 580 = 42862.58`；抹成 `73.90` 就变成 `42862.00`，差 58 元）
- `tax_rate` 是百分比，保持 `double`，不在迁移范围

⚠️ **不建议本阶段顺手改**：模型里这些列声明为 `Float`，DB 换成 numeric 后读出来是 `Decimal`，
`Decimal * float` 会 `TypeError`。第二阶段要把模型改成 `Numeric(…, asdecimal)` 并全量排查金额运算，
这是第二阶段工作量最大的一块，我会单独给清单。
