## 二、五个必须记住的坑

### 坑 1（★★★ 最狠）：`ctx` 解构会遮蔽 React Hook → 整页白屏，`vite build` 不报错

`pages/*.jsx` 顶部是 `extract_pages.py` 生成的固定套路：

```jsx
const { useState, useMemo, useEffect, ..., userProfile } = ctx;
```

而 `appCtx` 里**恰好也导出了 `useState` / `useMemo` 这些键**（生成脚本顺手导的）。
同一函数作用域里，后声明的 `const` 会覆盖 `import` 进来的 hook。运行时抛：

```
ReferenceError: Cannot access 'ca' before initialization
```

（`ca` 是压缩后的变量名，看不出来源。）

**致命之处：`npm run build` 完全通过，TypeScript 也没有，静态检查也不报——只有真在浏览器里打开这个页面才炸，而且是整页白屏。**

**解法**（四个页面统一）：

```jsx
import { useMemo as useLocalMemo, useState as useLocalState } from 'react';
```

**判断是不是踩了这个坑**：页面白屏 + 控制台 `Cannot access 'xx' before initialization` + `[ErrorBoundary] 渲染崩溃`（StrictMode 下出现两次）。

### 坑 2：变量名撞 `ctx` 键 = SyntaxError

`const summary = stockData.summary` 会撞 `ctx.summary`（往来对账用的那个）。
`vite build` 只报位置不解释原因：`Identifier 'summary' has already been declared`。

**解法**：改名 `stockSummary`。**新增页面里任何 `const` 之前，先 grep 一下 ctx 解构有没有同名键。**

### 坑 3：`ResizableLayout` 只认恰好 2 个子元素

抽屉挂在 `ResizableLayout` 同级时，会被当成第三个子元素，拖拽分割条直接失效。

**解法**：整个 `return` 用 `<>…</>` 包起来，让 `ResizableLayout` 仍然只收到 2 个 child。

### 坑 4：不要用正则改 JSX 属性

本轮给全站 17 个 `close-btn` 补 `aria-label="关闭"` 时，正则把箭头函数打断：

```jsx
// 原本
<button ... onClick={() => settle(false)}>
// 被改成了
<button ... onClick={() = aria-label="关闭"> settle(false)} aria-label="关闭">
```

`vite build` 报 `Expected "=>" but found "="`，涉及 6 个文件。

**解法**：精确回滚 + Babel 逐个 parse 确认。**教训：JSX 属性的批量修改必须走 AST，或者逐文件手工改。**

### 坑 5：`table-layout: fixed` 下 `min-width` 无效

项目台账操作列挤成三行，是因为 `min-width` 在 fixed 布局下被忽略，只认 `<col>` / 首行 `<th>` 的 `width`。

**解法**：

```jsx
<colgroup>
  <col style={{ width: 120 }} /><col />
  <col style={{ width: 90 }} /><col style={{ width: 92 }} />
  <col style={{ width: 72 }} /><col style={{ width: 110 }} />
  <col style={{ width: 104 }} /><col style={{ width: 168 }} />
</colgroup>
```

商品/项目名那一列不写 width = `auto` 吃余量。

## 三、`ErpDrawer` 的六条设计约束

写在组件注释里，改之前先读：

1. **`z-index: 129`** —— 高于 `.modal-backdrop`（100），低于打印确认（150）。这样"抽屉里再开小弹窗"能正常叠。
2. **Esc 走捕获阶段 + `stopPropagation`** —— 否则内层弹窗的 Esc 监听会抢先把整串层级都关掉。
3. **`busy` 时禁关** —— 提交中按 Esc 不响应，防重复提交。
4. **不改 `.modal-*` 类** —— 只写 `.erp-drawer*` 独占类名，避免和现有弹窗互相污染。
5. **三档宽度** `sm=380 / md=520 / lg=760`，footer 用 `form="xxx"` 关联表单提交（按钮在 `<form>` 外面）。
6. **`data-erp-drawer` / `data-erp-drawer-backdrop`** —— 验收脚本靠这两个属性定位，别改名。

## 四、历史脏数据清理

`verify_fourflow_link.py` 的 B6b/B6c 两红，一开始看着像 PATCH 接口坏了。

**真因**：上一次跑脚本把 `logistics_company="顺丰"` 留在了库里（测试没清理），本次 `before` 快照记下的正是这个脏值，
于是"清空后应等于快照值"这条断言天然不成立。

**排查方法**：手写 `/tmp/probe_log.py` 直连接口，确认 PATCH 清空行为完全正确
（`company=None, signed_at=None`）→ 断定是数据问题不是代码问题。

**解法**：写一次性脚本清掉所有 outbound 单残留的物流/签收数据（清掉 `id=4573`），复跑 **35/35 通过**。

> **教训：验收脚本会污染库。** 涉及"写入-回读-清理"的脚本，必须在 `finally` 里把写过的字段复位，
> 否则第二次跑必然红，而且红得很有迷惑性。

## 五、DataioPage 死文件清理的连带修复

v72 清理导入导出死代码后，页面里遗留了 15 个 `excel* / download* / runExcelImport` 解构项。
`verify_pages2.cjs` 因此报 **540 条"解构缺键"**。

## 六、金额口径的坚持（没改，但必须记住）

这次重构动了大量展示层，**但金额相关一行没动**，因为它们是硬约束：

- 金额/合计/税额 → `Numeric(…,2)` + `toFixed(2)`
- **单价/数量是"费率"** → `Numeric(14,4)`，最多 4 位**不截断**（`73.901×580=42862.58`，抹 2 位就错）
- 合计必须**逐行金额累加**，不能"总价 × 总量"
- **`step="0.01"` 是隐藏的价格改写器** → 金额/单价/数量/税额一律 `step="any"`
- `Math.round(n*100)/100` 会舍错 `1.005` → 用 ``Math.round(Number(`${n}e2`))/100``

库存看板新增的"库存总金额"沿用 `StockItem.estimated_value`，口径 = 数量 × 商品档案采购价，**不含运费税费**，
并在界面上明确写了这句提示（可点的那张卡点了会弹 notice 说明）。
