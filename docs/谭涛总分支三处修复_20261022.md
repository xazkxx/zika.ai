# 谭涛总分支三个问题的定位与修复（2026-10-22 · 第三轮）

> **版本 v164 · 20261022-1253**（PWA `erp-pwa-v164`），纯前端。
> 结论先说：**角标 8 是对的**（2 直挂 + 王宪全 4 + 陈银贵 2），错的是"那 2 个直挂客户没渲染出来"。

---

## 问题 1：角标 8，展开只数到 6

### 真相

数据库里 谭涛总(id=325) 的真实构成：

```
谭涛总 325          直挂 2 个客户（甲47000022、甲47000008）
├─ 王宪全经理 328    4 个
└─ 陈银贵经理 329    2 个
                    合计 8  ✓ 角标没错
```

少的 2 个正是**直挂在"谭涛总"自己身上**的那两条 —— 它们根本没渲染出来。

### 根因：叶子槽位的 Map 键撞车

`leafSlots` 原来用 `Map<"子树最后一个可见行的下标", 客户[]>` 记录"这组客户挂在哪个位置后面"：

```js
let end = i;                                     // 自己
for (j = i+1; …) if (rows[j].depth <= row.depth) break; else end = j;
out.set(end, kids);                              // ← 用 end 当 key
```

谭涛总的子树末尾 = 陈银贵经理那一行；而陈银贵自己**没有更深的后代**，
它的子树末尾**也是这一行**。于是 `out.set(同一个下标, …)` 后写的把先写的**整组覆盖** ——
父级直挂的 2 个客户就这么消失了。

### 改法

叶子改挂到**节点自己这一行之后、子分类之前**（用户口径："出现在所有子分类的上方"），
`Map<行自身下标, 客户[]>` 不再可能撞车。

顺带说明用户"数不到 8"的另一个原因：**手风琴**让 王宪全 / 陈银贵 不能同时展开，
所以逐个数叶子永远只能数到一半 —— 这是设计，不是 bug。角标的算法在验收里被钉死为
`badge(父) = 父直挂叶子数 + Σ badge(子)`。

## 问题 2：拖不进谭涛总

### 真相

拖拽本身是好的。真正点不进去的是**拖到客户叶子（文件）上松手** ——
叶子是分类行的**兄弟节点**（不是子节点），它当年没有挂 drop 处理器，
所以 drop 落在叶子上既不冒泡到分类行、也没有自己的处理 → **彻底静默**，连提示都没有。

用户在"谭涛总"下方看到的两条客户（蒲白330…、西安东750…），正是最容易瞄准的落点，
于是手感上就是"怎么拖都没反应"。

### 改法

1. **客户叶子自己也是合法落点**：`data-leaf-owner` 记下所属分类，drag/drop 时落到该分类。
   语义也自然 —— 把文件拖到另一个文件上，意思就是"放进它所在的文件夹"。
2. **每个分类行都挂了 drop props**（有子分类 / 有客户 / 什么都没有，一视同仁），
   已在巡检里逐个验证。
3. **拖到自己本来所在的分类**时，后端 `moved=0`，以前什么都不提示；
   现在明确说「这些客户本来就在「谭涛总」下，没有需要移动的」。

## 附带修好的：深层节点名字被挤成 "L5"

截图里「王宪全经理」显示成 `L5 4`，看起来像名字没渲染。实际是两个占位叠加：

| 占位 | 宽度 |
|---|---|
| `.ptree__acts`（+ / 改名 / 删除按钮组）用 `opacity:0` 隐藏 | **仍然占 ~60-70px** |
| `.ptree__depth`（L5 角标，`flex:0 0 auto`） | ~22px |
| 4 层缩进 `8 + 4×14` | 64px |

树栏只有 300px 上下，三样一挤，`.ptree__label` 被压到 0 宽 —— 界面只剩 "L5"。

改法：
- 按钮组改**绝对定位**（平时完全不吃宽度，悬停时浮在计数角标上，角标让位）；
- 深度角标改为**悬停/选中才显形**（`width:0` → `auto`）；
- `.ptree__label` 加 `min-width: 3.2em` 保底：至少能看到 2~3 个字 + 省略号。

现在 4 层的「王宪全经理」「陈银贵经理」「陕西送变电工程公司」都是完整可读的。
