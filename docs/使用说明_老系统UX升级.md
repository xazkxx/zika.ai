# 使用说明：老系统 UX 升级（复制行 / 批量选商品 / 三维状态 / 反审核）

> 更新日期：2026-10-20（PWA v65）。本文写给不写代码的业务同事，全程零术语。

---

## 一、这次加了什么（一句话版）

1. **复制行**：录单时不用再一行一行重新填商品。
2. **批量选商品**：勾一勾、搜一搜，一次带进一串商品。
3. **列表三种颜色小牌子**：一张单审没审、收没收钱、发没发货，一眼分清。
4. **反审核**：单子审错了可以"撤回来"重新改（有条件的，见下文）。

---

## 二、在哪儿、怎么用

### 1. 复制行
**入口**：销售订单 / 采购订单 / 销售出库 / 采购入库 的【单据录入弹窗】明细表格，每行末尾多了「复制」按钮；列表页工具栏还有「复制选中行」（先在列表勾选行）。

**操作**：点一下，整行商品、单价原样复制一份追加到表格最后，**数量自动重置为 1**。
**为什么数量清成 1？** 复制通常是为了"再买/再卖一件同样的东西"，保留原数量容易多录。想多件直接改数字。

### 2. 批量选商品
**入口**：同一批录入页的工具栏，「批量选商品」按钮。

**操作**：弹窗里可以在**顶部搜索框**按商品名 / 编码 / 拼音助记码 / 分类搜，勾选多个，点「带入」，它们会一次性追加到明细表末尾。
**价格怎么来？** 系统自动按商品档案里的默认销售价 / 采购价填入，单据类型不同取的价不同；没有维护默认价的商品会填 0，**记得手改**。

### 3. 多维状态分离（三种小牌子）
以前列表只有一列"状态"，一张单"审了没、收了没、发了没"混在一起说不清。现在按单据类型拆成最多三列彩色徽标：

| 单据页 | 审核状态 | 收付款状态 | 发货/转单状态 |
|---|---|---|---|
| 销售订单 / 采购订单 | ✔ | ✔ | ✔（看是否已转单） |
| 销售出库 | ✔ | ✔ | ✔（看是否已签收） |
| 采购入库 | ✔ | ✔ | — |

颜色规则：**灰**=还没动（草稿/未提交），**橙**=进行中（已提交待办），**绿**=办妥（已审核/已结清/已发货），**红**=有欠款（会写明欠多少钱）。

### 4. 反审核
**入口**：销售订单、采购订单列表页，操作列的「反审核」按钮——**只对已审核、还没有转单的订单出现**。

**操作**：点一下，单子退回「草稿」，可以继续修改后再提交审核。
**哪些情况点不动 / 会拦？**
- 已经转出库单 → 后端拦截（提示"已产生库存/资金流水"）；
- 已经收款 / 产生账 → 拦截；
- 已经完成（已转单）→ 拦截。

**为什么出库单、入库单页没有反审核按钮？** 这两类单据**创建时就会记账和动库存**，按系统安全规则有账的单不能随便退回草稿，必须走「红冲」流程冲正。所以反审核只放在纯流程的订单页上——这是有意设计，不是漏做。

---

## 三、防呆提示

1. 反审核不是"删单"，只是退回草稿；要彻底删单仍走原来的删除入口（同样受"有账不能删"的闸口保护）。
2. 批量选商品带入后请核对单价，默认价没维护的商品是 0。
3. 看到红色欠款徽标别慌，那是提醒你去收款/付款，点单据进详情能看到明细。

## 四、技术备注（给维护者）

- 状态文案：出库单改用 `OUTBOUND_STATUS_LABELS`（completed=已发货），不再复用订单的"已转单"文案。
- 反审核接口：`PATCH /sales-orders/{id}/unsubmit`、`PATCH /purchase-orders/{id}/unsubmit`，服务端检查 `InventoryTransaction` / `FinancialTransaction`（related_type `sales_out`/`receipt` 与 `purchase_in`/`payment`）。
