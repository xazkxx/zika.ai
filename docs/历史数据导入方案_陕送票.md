## 三、导入方式（已跑通，不是纸面方案）

### 3.1 落点：建成「销售出库单」

| 项目 | 取值 | 为什么 |
|---|---|---|
| 单据类型 | `doc_type=outbound` | 历史单是已发货已结算的事实，不是意向 |
| 单据状态 | `submitted` | `unsubmit_sales_order` 有硬闸：有库存/资金流水就不许退草稿 |
| 库存流水 | **每个明细行 1 条** | 与 `create_sales_order` 口径一致 |
| 应收流水 | **整张单 1 条** | ⚠️ 收款登记按单冲减；一单挂 18 条应收，出纳不知道冲哪条 |
| 会计凭证 | 借贷双分录 | 由 `_write_finance` 自动过账生成 |
| 单号 | `XS` + 年月日 + 3 位流水 | 13 位，走 `next_seq` 按数值取最大（不能用 `ORDER BY order_no DESC`，字符串序会撞号） |
| 备注 | `历史导入\|源单号=XS...\|来源=xxx.xls` | **幂等唯一依据**，也是日后回滚的认人标记 |

**不选「只建销售订单」**：那样不动库存、不产生应收，账实不符，等于把问题推到以后。

### 3.2 拆单：一张源单跨多个工程 → 按工程拆开

源数据里 **14 张单跨 2~4 个工程**（同一份清单抄给多个工程，或一车货分送多个工点）。
系统 `sales_orders` 只有一个 `customer_id`，硬塞成一张 = 其他工程的货挂到第一个工程名下，
**应收永远对不上工程款**。

处理：按「单号 + 工程」拆，子单外部单号加 `-01 / -02` 后缀（保证幂等键唯一）。

实测效果（对账总表 131 行）：**31 张 → 34 张，其中 6 张是拆出来的子单，总额 ¥313,209.78 一分不变。**

### 3.3 状态机流过哪些

```
draft →（写库存 + 写应收 + 写凭证）→ submitted
```

不经过 `pending / approved`（那是销售订单的路）。`completed` 留给收款核销完成后自然流转。

### 一条关键设计（和档案导入反着来）

档案导入（客户/商品）是「单行失败就记错误、其余继续」——少建一个客户不影响别人。
**单据导入不能这样**：18 行的单丢了 3 行，金额就少了，状态照样报"成功"。
这种半截数据比明确失败危险得多。

所以本引擎：**任何一行有问题 → 整张源单一行都不导**。而且判定键是**单据号**
（不是"单号+客户"——坏行往往正是因为客户名认不出，用客户名当键永远匹配不上，
整单会静默放行）。宁可整单等人工修表，也不要"三个工程导了两个、账上少一笔还显示成功"。

### 5.2 45 处「同一单里同名商品同量同价出现多次」（¥70,823.07）

典型例子 `XS202508060002`（2025-08-06，18 行）：

| 工程 | 商品 | 数量 | 单价 | 金额 |
|---|---|---:|---:|---:|
| 蒲白750包1 | 金属制品80烧水桶 | 4 | 400 | 1,600 |
| 陕北通道包12 | 金属制品80烧水桶 | 4 | 400 | 1,600 |

这两行**逐字相同**，9 个商品全部这样成对出现。

两种解释，账上完全不同：

- **抄重了**（只该有 1 份）→ 按 2 份导 = **虚增收入 ¥70,823.07 + 虚增出库**
- **真的各发一份** → 按 1 份导 = **少记收入 ¥70,823.07**

脚本不做判断，只把 45 组全部列进 `风险_重复行.csv` 交给你。

**需要你确认：这批"两个工程同名同量同价"的，实际是各发一份，还是一份货摊到两个工程记账？**
