# 合同 OCR 识别 · 使用说明

> 给业务同事看的操作手册。看不懂代码没关系，照着做就行。

---

## 一、这个功能是干什么的？

以前录合同，要一边看着纸质的（或扫描的）合同原件，一个字一个字敲进系统。

现在系统可以**自动"读"合同原件**：你把合同原件（PDF 或照片）传上去，点一下「开始识别」，系统就会自动认出：

- 合同编号
- 合同名称（标题）
- 对方单位（客户 / 供应商的名字）
- 合同总金额
- 签订日期
- 付款方式
- 明细行（买了什么、数量多少、单价多少）

认出来之后，可以**一键填进表单**，不用再手敲。

**两种用法，任选一种：**

| 场景 | 用哪个 |
| --- | --- |
| 新签一份合同，还没录进系统 | **新建弹窗里直接识别**（推荐，见第三节） |
| 合同已经在系统里了，想补识别 / 重新识别 | 到「详情」里识别（见第四节） |

---

## 二、功能入口在哪里？

**销售管理 → 合同台账**（采购合同也一样，在合同台账里切到「采购合同（进）」页签）。

- 新建：点右上角 **「新增销售合同 / 新增采购合同」**
- 已存在的合同：点列表里那一行 → 打开「详情」

---

## 三、新建合同：先识别、后填表（推荐）

这是最省事的流程——**不用先保存合同**，弹窗里就能传原件、直接识别。

### 第 1 步：打开新建弹窗，先选原件

点「新增销售合同」，弹窗**最上面**就是 **「合同原件与智能识别」** 区块。

点「选择文件」，选出这份合同的 PDF 或照片。

- ✅ PDF（最准最快）
- ✅ 照片 / 图片（PNG、JPG、BMP）
- ⚠️ Word 文档（.doc / .docx）**不能直接识别**：你在选文件时就会被系统温柔拦一下，按钮上方会出现一条**黄色提示**，告诉你「另存为 PDF 再上传」，同时「开始识别」按钮保持灰色点不动 —— 这样你不会白等一场，也不会白传一份传不上去的文件。

> **Word 怎么转 PDF？** 打开 Word → 左上角「文件」→「另存为」→ 保存类型选 **PDF** → 保存。然后回这里上传那个 PDF 就行。
> （Word 原件本身仍然可以存档：先把合同存下来，进合同详情页上传 Word 当作"附件留底"，只是它不参与识别。）

选完文件，系统会自动把它暂存起来（显示「已暂存：文件名（大小）」），**这时还没有建合同**。

### 第 2 步：点「开始识别」

原件就绪后「开始识别」按钮变亮，点它。屏幕上会出现一条**会动的扫光**，表示系统正在读合同，一般几秒钟，最多两分钟。

> **页数多的合同**：系统最多读前 10 页（合同的关键信息——编号、金额、双方、付款方式——几乎都在前 10 页）。
> 超过 10 页时结果里会提示「只识别了前 10 页」，这不是出错，后面的条款靠人工看一眼就行。

### 第 3 步：看识别结果，选择怎么填

识别完成，区块里会显示：

- **认出了什么**：编号、标题、对方单位、金额、签订日期、付款条款（一张张卡片）
- **识别到的明细**：名称 / 数量 / 单价 / 金额 一张小表
- **原始识别记录**（折叠着，点开能看原文，有争议时对质用）

然后分两种情况：

#### 情况 A：表单还是空的（最常见）

系统会**自动把识别结果填进表单**，并提示「表单原为空，已自动填入识别结果，请核对」。

#### 情况 B：你已经手填了内容（重要！）

系统会**先问你**，绝不自动改你填的东西。会出现一条黄色提示：

> **检测到你已填写：合同标题、客户、2 行明细**
> 识别结果不会自动盖掉你填的内容。请选择怎么处理：

三个按钮：

| 按钮 | 效果 | 什么时候用 |
| --- | --- | --- |
| **仅填充空白字段**（推荐） | 你填过的一个字都不动，只把空着的项（比如付款条款、明细）补上 | 大部分情况 |
| **用识别结果覆盖** | 整块替换，连明细一起换成识别的 | 确认自己填错了、想全用识别的 |
| **暂不填充** | 什么都不改，识别结果只留作参考 | 只是想过一眼 |

填完会显示一行绿色提示，告诉你用了哪种方式（「已只填入空白项，你填写的内容未改动」之类）。

#### 情况 C：客户档案里没有这家（很常见，别去别的页面）

识别出来的名字填进表单了，但档案里查无此人，会出黄色提示：

> 未匹配到系统客户「湖南华邦建设有限公司」，已保留识别到的名称。请点开下拉手动选一次，否则保存会被拦。

这句话下面还挂着一个蓝色链接 **【+ 一键新建该客户】**。点它，会弹出一张精简表单：

| 项 | 说明 |
| --- | --- |
| 客户名称 | **已经填好了**（就是识别到的名字），一般不用改 |
| 客户编码 | **留空就行**，保存时系统自动生成（`CUS` + 日期 + 流水号） |
| 联系人 / 电话 / 地址 / 备注 | 都可以先空着，以后到「基础资料 → 客户档案」补 |

点 **「保存并使用该客户」** → 弹窗自动关闭 → 合同表单里的客户**自动选中**、黄色提示消失、顶部提示「已新建客户「…」并选中」。接着点「保存合同」即可，不用再跑一趟基础资料、也不用重新识别。

> 系统会先查一遍同名档案：如果这个名字其实已经有了（只是刚才没匹配上），它**不会重复建**，直接帮你选中那一条，并提示「已直接选中」。两家同名客户是最难查的脏数据，所以这里宁可少建一条。

### 第 4 步：核对，然后点「保存合同」

逐项核对表单（标题、对方、日期、明细数量单价），没问题点 **「保存合同」**。

这一步会**一次性**保存：合同内容 + 明细 + 原件文件 + 识别记录。保存后自动打开这份合同的详情，原件显示「已上传」，OCR 状态是「已人工核对」。

> 看图核对两个地方：
> ① **单价**允许带 3~4 位小数（如 `73.901`），这是正常的，不要手动抹成 `73.90` —— 抹掉会让合计少几毛钱（见第五节第 6 条）。
> ② **金额和合计永远是两位小数**。如果合计跟你按计算器算的差 1 分钱以内，是正常的四舍五入；差几毛钱就说明有单价被改过。

> 点了「暂不填充」再保存的情况：合同里的内容跟识别结果无关，所以 OCR 状态会记成「已识别待核对」而不是「已人工核对」——系统不会替你撒谎说"核对过了"。

### 不想建了？

直接点「取消」或右上角 ×，暂存的原件会自动丢掉，不会在服务器上留垃圾（万一没丢干净，24 小时后也会被自动清理）。

## 四、已存在的合同：在详情里识别

1. 合同台账里点某一行 → 打开「详情」
2. 找到「合同原件」区域 → 点「上传原件」选文件（可以替换）
3. 点 **「开始识别」** → 等扫光结束
4. 看识别结果：字段卡片 + **识别 vs 合同对照表**（一样绿、不一样红）+ 原始识别记录
5. 想用识别结果？点 **「一键回填表单」**——它会打开一张**新的合同表单**（不会改已保存的这份合同）
6. 核对完点 **「确认无误」**：状态变「已人工核对」，按钮随即变成灰底的 **「✓ 已完成核对」**，下方出现一行说明"识别结果已人工核对完成，无需再确认；如需重做请点上方「重新识别」"——灰按钮点不动是**故意的**，不是卡死
7. 核对无误、合同也确实谈定了 → 点底部的 **「确认生效」**：合同状态从「草稿」变「生效」，列表里的徽章同步变色

> **注意**：识别按钮会跟着状态变名字。状态是「已人工核对」时，它叫 **「重新识别」**，点下去会先弹一个二次确认——因为重新识别会把你核对过的结果覆盖掉、状态退回「已识别待核对」。

## 五、核心业务规则（为什么这么设计？）

### 1. 为什么识别结果必须人工核对？

机器识别**不是百分百准确**。印刷清晰的 PDF 基本没问题，但手写的、模糊的、拍照反光的合同，"1"可能认成"7"、"元"可能认成"方"。

金额认错一个字，合同金额就差十万八千里。所以识别结果一律当**草稿**，必须由人核对。状态叫「已识别待核对」而不是「已完成」，就是这个意思。

### 2. 为什么「确认无误」不改合同上的内容？

你可能注意到：详情里点「确认无误」后，合同上的客户、金额**一个字都没变**。

这是故意的。如果系统把识别值自动盖到合同上，万一认错字，**一份本来填对的合同反而被改错了**。所以：合同内容以人工填写为准；识别结果只用来回填新表单或做核对标记。

### 3. 为什么新建时已经手填的内容不能被自动覆盖？

因为在弹窗里填表的人，往往比 OCR 更清楚实际情况——比如他刚跟客户打完电话确认了金额。机器认错了却把人填的盖掉，等于把唯一正确的那份数据毁了。

所以系统的规则是：**只要检测到你填过，就一定先问，默认只补空白。**

### 4. 为什么匹配不到客户/商品档案时不自动选？

系统按名字找档案，分三种情况处理，**唯一原则是不猜**：

| 情况 | 系统怎么做 | 你会看到 |
| --- | --- | --- |
| 名字**一字不差**（忽略空格、括号、"（盖章）"） | 直接选中档案 | 框里是正常名称，没有提示 |
| 名字**只对上一部分**，且档案里只有一家包含 | 选中，但标注"要你确认" | 一条**蓝色**提示：按名称相似匹配到「…」，请确认 |
| 档案里有**两家以上**包含同样的字，或完全找不到 | **不选**，只保留文字 | 一条**黄色**提示：未匹配到系统客户，请点开下拉手动选一次 |

为什么"两家以上包含"就放弃：搜"西安"能同时命中十家公司，猜哪一家都是事故（钱记到别人头上）。

为什么"只对上一部分"还给你选：合同上常写简称（"西安寨卡" vs 档案里"西安寨卡信息技术有限公司"），全放弃就得每次都手点。折中办法是选了但**明确告诉你这是猜的**，你扫一眼就能确认。

### 5. 为什么提示"表单原为空"和"你已填写"差别这么大？

系统把"用户主动填的"和"表单天生的默认值"分开看：

- 标题默认「销售合同 / 采购合同」、日期默认今天、税率默认 13% —— 这些**不算**你填过；
- 只要标题改成别的、选了客户、填了付款条款、写了备注、加了明细 —— 才算"你填写的内容"。

这样既不会动不动就弹警告，也不会漏掉真正的冲突。

### 6. 为什么单价可以写 73.901，金额却只有两位小数？

因为这是两种完全不同的数：

- **金额是"钱"** —— 一分钱就是最小单位，多出来的第三位没有意义（现实里付不出 0.001 元）。所以金额、合计**永远四舍五入到两位**。
- **单价是"费率"** —— 73.901 元/米 是含税价和不含税价换算出来的真实值，不是随手写的。它乘上 580 米才是钱。

举个真实例子（这份 261 万的合同里就有）：

| 写法 | 算式 | 结果 |
| --- | --- | --- |
| 保留 3 位（正确） | 73.901 × 580 | **42,862.58** |
| 抹成 2 位（错误） | 73.90 × 580 | 42,862.00 |

一行差 0.58 元，五行加起来合计就少了 0.58 元 —— 这就是"表单合计 2,617,568.02、存进去却是 2,617,567.44"的全部原因。

所以系统的规矩是：**单价/数量最多 4 位不截断，每行金额算完立刻定成两位，合计只做"逐行金额相加"**（不用"总数量 × 平均单价"，那又会引入新的误差）。

> 你之前提的"把价格也 toFixed(2)"，如果真那么做，反而会制造这个尾差 —— 所以这里落地成了"价格保 4 位、金额保 2 位"。

### 7. 为什么「确认生效」要单独一个按钮？

「核对过识别结果」和「这单生意算数了」是**两件不同的事**。

前者只是说：我把机器认出来的字跟原件比对过一遍，没错。后者是说：这份合同正式成立，后面要据此排产、发货、对账。所以系统不把两者绑在一起——你随时可以核对 OCR，但只有你主动点「确认生效」，合同才会进入后续流程。

按钮只在「草稿」和「待审核」两个状态出现。已经生效的合同不会再有这个按钮，避免误点造成重复流转。

### 8. 为什么重新识别要弹二次确认？

因为「已人工核对」这个状态是你花时间换来的——把识别结果一条条跟原件比对过的成果。

机器重新识别一遍，会把 `ocr_status` 退回「已识别待核对」，你之前核对的结论就没了。如果按钮还是老老实实叫「开始识别」、点了就跑，很容易手滑把半天的活冲掉。

所以：状态一旦是「已人工核对」，按钮改名「重新识别」，并且点下去先问一句「重新识别将覆盖当前已核对数据，是否继续？」。选了「取消」，一个字都不会动。

## 六、防呆提示（遇到这些怎么办？）

| 提示 / 现象 | 原因与解决办法 |
| --- | --- |
| 「开始识别」按钮是灰的 | 还没选原件。先点「选择文件」，等显示「已暂存」。 |
| 选了 Word，出现一条**黄色**提示、按钮还是灰的 | 这是正常的温柔拦截，不是报错。Word 不能直接识别，请在 Word 里「另存为」PDF 再上传。 |
| 提示"只支持 PDF / PNG / JPG / BMP" | 格式不对（比如传了 OFD / WPS / 加密 PDF）。Word 请先另存为 PDF。 |
| 结果里提示"只识别了前 10 页" | 合同超过 10 页，系统只读前 10 页（关键信息基本都在前面）。不是错误。 |
| 提示"临时文件已过期或不存在" | 弹窗放了超过 24 小时没动，暂存被清理了。重新选一次原件即可。 |
| 提示"识别失败"或"没有认出任何文字" | 原件太模糊 / 是空白扫描件 / 是加密 PDF。换一份更清晰的再试。 |
| 识别出来的金额是空的 | 合同上金额没带"金额 / 总价 / 合计"这类字样，或只写了"总价的 30%"这种比例。系统**故意不认**（避免把电话、页码、比例当金额），手填即可。 |
| 识别出来的对方单位是空的 | 合同里没有"甲方：/乙方："这种带冒号的写法，或名字不像单位名。系统**宁可空着也不猜**，手填或从档案里选即可。 |
| 出现黄色"检测到你已填写" | 这是保护，不是报错。默认选「仅填充空白字段」最安全。 |
| 点了「仅填充空白字段」，明细没变？ | 因为你已经填过明细了。想换成识别的明细，请选「用识别结果覆盖」。 |
| 客户框里**有名字**，点保存却提示「只是显示的文字，还没选中系统档案」 | 这叫"假选中"：识别到了名字，但档案里没有正好对应的那家（或有两家以上对得上），系统不敢替你认。**点黄色提示下面的【+ 一键新建该客户】**，或点开下拉从列表里点一次，提示会自动消失。 |
| 出现蓝色「按名称相似匹配到 …，请确认是不是同一家」 | 系统按简称猜中的，已经帮你选好了。扫一眼：是同一家就继续填；不是就重新选一次。 |
| 单价栏显示 73.901、合计带 .02 这种零头 | 正常，不要手改。单价是费率（最多 4 位），金额/合计才两位（见第五节第 6 条）。 |
| 合计比我自己按计算器算的少几毛 | 说明有单价被手动改成了两位。单价别动，改回原值合计就对上了。 |
| 点了【+ 一键新建该客户】，保存时提示「编码已存在」 | 有人用同一个编码建过档案。把编码框**清空**再保存即可（留空会自动生成）。 |
| 保存后发现 OCR 状态是「已识别待核对」 | 保存前选了「暂不填充」——合同内容与识别无关。想标记核对过，到详情里点「确认无误」。 |
| 提示要重启 ERP | 后端服务升级后还没重启。联系管理员双击「启动ERP.bat」。 |
| 识别按钮从「开始识别」变成「重新识别」了 | 这不是故障：合同的 OCR 状态已经是「已人工核对」，按钮改名 + 二次确认，就是为了防止手滑把核对结果冲掉。 |
| 「确认无误」变成了灰色的「已完成核对」，点不动 | 这是**正常状态**，不是卡死：核对已经做完了，系统不希望你再点一次。想重做就点上方「重新识别」（会先问你一句）。 |
| 导出的 Word 双击打不开 / 提示文件已损坏 | 说明那次下载拿到的不是 Word 文件（多半是服务端报了错）。点「导出 Word」时界面若提示"导出失败…"，按提示处理即可；如果是浏览器把下载拦了，让管理员换一台机器或用 Chrome 重试。正常文件大小一般 30KB 以上，见说明书最后一节的自检方法。 |
| 「确认无误」变成了灰色的「已完成核对」，点不动 | 这是**正常状态**，不是卡死：核对已经做完了，系统不希望你再点一次。想重做就点上方「重新识别」（会先问你一句）。 |
| 导出的 Word 双击打不开 / 提示文件已损坏 | 说明那次下载拿到的不是 Word 文件（多半是服务端报了错）。点「导出 Word」时界面若提示"导出失败…"，按提示处理即可；如果是浏览器把下载拦了，让管理员换一台机器或用 Chrome 重试。正常文件大小一般 30KB 以上，见说明书最后一节的自检方法。 |
| 点「重新识别」弹出「将覆盖当前已核对数据」 | 二次确认，不是报错。要继续就点「继续重新识别」，不想动就点「取消」——取消后一个字都不会变。 |
| 详情页找不到「确认生效」按钮 | 只有「草稿」和「待审核」的合同才有。已经生效的合同不会再显示，避免重复流转。 |
| 点「确认生效」提示没有权限 | 生效属于管理动作。找有权限的账号，或让管理员在【系统管理 → 角色权限】里给这个角色勾上合同的状态流转权限。 |

## 八、自检：导出的 Word 到底是不是好文件？

不用装任何工具，浏览器自带的面板就能看。

**第一步：打开面板**
按 `F12`（或右键 → 检查）→ 切到 **Network（网络）** 标签 → 点一下左上角的 🚫 图标清空，保持面板开着。

**第二步：点「导出 Word」**
列表行上的「Word」按钮、或详情里的「导出 Word」都行。

**第三步：看这一行**
面板里会多出一条 `exports/word/contract/123` 这样的请求，点它：

| 看哪里 | 正常应该是什么 | 不正常长什么样 |
| --- | --- | --- |
| Status（状态） | `200` | `401`（登录过期）、`404`（单据没了）、`500`（生成失败） |
| Response Headers → `content-type` | `application/vnd.openxmlformats-officedocument.wordprocessingml.document` | `application/json` ← **这就是"存下来打不开"的元凶**：服务端其实返回了一段报错文字，却被当成文件存了 |
| Response Headers → `content-disposition` | `attachment; filename*=UTF-8''…docx` | 没有这一行 → 说明走的不是下载通道 |
| Size（大小） | 一般 **30KB 以上** | 几十字节 → 一定是报错文本 |
| Response（响应）标签 | 显示 **Binary / 二进制**，或一堆乱码 | 显示 `{"detail": "…"}` ← 一目了然 |

**第四步（可选）：确认文件本身**
下载完在文件夹里右键 → 属性，大小同样是 30KB 上下；用记事本打开它，第一行应该是乱码 `PK` 开头（Word 文件本质是个压缩包），而不是 `{"detail":…}`。

> 本版已加**硬闸**：拿到不是 docx 的内容时，界面会直接提示「导出失败：服务端返回的不是 Word 文件（原因…）」，**不会**再存一个打不开的 `.docx` 让你猜。
