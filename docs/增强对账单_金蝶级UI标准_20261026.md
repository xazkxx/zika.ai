# 增强对账单 · 金蝶/用友级 UI 标准（v1.77.0）

> 日期：2026-10-26 · 版本：1.76.0 → **1.77.0**
> 这份文档有两个用途：
> ① 记下「增强对账单」这一页**为什么长成现在这样**（决策 + 踩过的坑）；
> ② 作为**铺开到其它页面的施工标准** —— 下一批页面照着第 3 节的六条硬规则做即可。

## 1. 目标（用户原话）

> "对账单要像金蝶/用友那样，看着专业、干净，一屏就知道该点哪个按钮；
>  四流穿透不能减弱，导出要能直接发给客户。"

拆成四条可验收的标准：

| # | 标准 | 验收方式 |
| --- | --- | --- |
| A | 一屏只有**一个**主按钮，次要/低频动作收进 `⋯` | 截图 2/5 |
| B | 顶部一句话即可开工（AI 指令条常驻页面内，不是弹窗） | 截图 2 |
| C | 四流穿透：分组可辨、断流一眼看见、能逐行钻取 | 截图 3/4 + `_dbg_stmt_box.cjs` |
| D | Excel/Word/PDF 拿出去就能发客户（抬头、斑马纹、冻结、打印标题、页码） | 真实 xlsx + `smoke_export_style.py` |

## 2. 版面骨架（自上而下五段，铺开时按同一顺序）

```
┌ AI 指令条（SmartCommandBar compact + onOpenStatement）   ← B
├ 命令区：分段(全部/应收/应付) + 往来单位 + 账期 …… [载入已存对账单] [搜索预览]
│        第二行右侧：[重算] [保存(主)] [⋯]                 ← A
├ 单据头 + KPI 计量条（期初/本期新增/已开票/已收/期末应收）
├ 明细表（深蓝表头 · 斑马纹 · 勾选参与本单合计）
└ 四流穿透明细（分组着色表头 · 断流色条 · 点行开抽屉）      ← C
```

- **单据头 KPI 的"计量条"**：每张卡片底部有一条按占比填充的细条（期末应收那张高亮蓝），
  让人不用读数字就知道哪一项占比最大。
- **明细表**：`striped` + `hover` + 深蓝表头 + 右侧吸顶「操作」列。
- **四流表**：表头左侧 3px 分组色带 + 分组表头浅色底 + 明细行首列色条。

## 3. 六条硬规则（施工标准）

1. **单主按钮**：一屏只允许一个 primary（`保存`）。打印/导出这类"收尾动作"一律进 `⋯`。
2. **`⋯` 收纳**：用 `ErpMoreMenu`（`ui/ErpMoreMenu.jsx`），每项带一行 hint 说明产物。
   已在用：打印 PDF / 导出 Excel / 导出 Word；**不要**把 `.modal-*` 或 `ErpSearchSelect` 往这上面套。
3. **深蓝表头 + 斑马纹**：表头 `#1f3a5f` 系、正文 `#F7F9FC` 隔行；金额列右对齐 + `tabular-nums`。
4. **分组必须"看得出是一组"**：分组表头 `data-tone` → 上沿 3px 色带；
   `is-group-start` 打组间隔线、`is-frozen-edge` 给冻结列加右阴影。
5. **断流要看得见**：按**单据块**聚合判定 —— 整单未开票 = 红条（stop），部分开票 = 黄条（warn）。
   页面右上还有「断流 N 张」胶囊，点它可只看断流单据。
6. **打印/导出同源**：页面样式与导出样式**分别**实现，但字段与列序必须一致；
   `@media print` 里把吸顶表头、抽屉、`⋯` 面板全部 `static/hidden`，
   页眉用 `&D &T` 域打印"打印时刻"而不是"导出时刻"。

## 4. 组件 API（照抄即可）

```jsx
// ① AI 指令条嵌进任何单据页（不传 onOpenStatement = 工作台老行为，零变化）
<SmartCommandBar
  apiBase={apiBase} authHeaders={authHeaders}
  compact
  placeholder="说一句话就能开单：给我湖南华邦这个月的对账单"
  onOpenStatement={({ statementId, party }) => { ... }}
/>

// ② 收尾动作收纳
<ErpMoreMenu
  testId="statement"
  items={[
    { key: 'print', label: '打印 PDF', hint: 'A4 横版 · 可直接发给对方', onSelect: printStatement },
    { key: 'excel', label: '导出 Excel', hint: '台账 + 明细两张表 · 含合计', onSelect: exportExcel, disabled: busy },
    { key: 'word',  label: '导出 Word',  hint: '可盖章发送 · 适合存档', onSelect: exportWord, disabled: busy },
  ]}
/>
```

`StatementEditor` 内部新增：`previewPool(override)` 支持显式参数（AI 条把认出的单位直接送进来，
不用先 `setState` 再等一拍）、`openFromAgent`、`primaryIsSave`（决定主按钮是"搜索预览"还是"保存"）、
三张表统一 `striped`/`hover`。

## 5. 导出升级（后端 `app/services/doc_export.py`）

| 项 | 改法 |
| --- | --- |
| 抬头 | 第 1 行只放账套 `own_name`（用户拍板：**不加**制表人/审核人） |
| 标题/副标题 | 第 2/3 行：单据名 + `共 N 条　导出时间：…` |
| 表头 | 深蓝底白字加粗，四边细边框 |
| 斑马纹 | 奇数行 `#F7F9FC` |
| 列宽 | `_autofit_columns()` 按内容 + 中文宽度估算（中文按 2 个字宽） |
| 冻结 | `freeze_panes` 到表头下第一行 |
| 打印 | `_print_setup()`：A4 横版、`fitToWidth=1`、`print_title_rows=$表头行`、页脚「第 &P 页 / 共 &N 页」、页眉「打印时间：&D &T」 |
| 状态字 | `_status_font()`：草稿=琥珀、已确认=绿、已作废=灰 |

`erp_export.py` 统一接 `company` query；不传时默认 `load_company(db)["own_name"]`（一张一张导出也不会没抬头）。

## 7. 踩过的坑（别重犯）

1. **`flex-wrap` + JSX 换行 = 多出半行高**：块里的空白文本节点会变成"匿名 flex 项"，
   把 38px 的行撑到 78px。命令区改成 `grid`（grid 不生成匿名项）后归一。
2. **`nowrap` 的不一定是不收缩的**：`flex: 1 1 auto` 的容器里，右侧按钮会被压成竖排文字；
   要 `.stmt__cmd-right > * { flex: 0 0 auto; }`。
3. **`summary`（单据小计）行没有 `invoice_status`**：开票状态只挂在 detail 行。
   所以断流判定必须**按单据块聚合**，否则色条永远不出现（第一次实现就踩了）。
4. **后端的折叠标记是 `◤`/`◢`，不是 `▾`**：表格里有用，抽屉里要去掉（正则要包含 `◤◢`）。
5. **`openpyxl` 不会自动套主题**：表头填充色、边框、`number_format`、`freeze_panes` 全部要手写。
6. **改了后端必须重启程序**：`dist` 刷新即生效，`app/services/*.py` 不会热更 ——
   验收时"导出还是旧的"十有八九是这个。
7. **旧 smoke 写死行号**（表头在第 3-8 行）在加了抬头行后必然误报 → 一律按文字 `find_row()` 定位。

## 8. 下一步（铺开到全局）

按"使用频率 × 单据复杂度"排序，建议顺序：

1. 销售订单 / 采购订单（命令区结构最像，直接复制五段骨架）；
2. 开单管理（有无物流签收流的差异点：多一条"签收流"分组即可）；
3. 采购对账单（与增强对账单**共用组件**，只换 scope 默认值）；
4. 剩余列表页只做第 3 节的第 1/3/6 条（单主按钮、深蓝表头斑马纹、打印同源），
   分组/断流这些强业务语义的部分不要硬套。

每铺开一页，必须同步：截图 5 张 + 一条 `smoke_export_style.py` 的断言（若该页有导出）。
