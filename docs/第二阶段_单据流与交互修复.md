> 交付时间：2026-10-20 · 对应菜单：客户/供应商档案、销售退货、购销合同、增强对账单、财务流水、报表中心

## 一、这一阶段改了什么（按你的清单）

### P2-1 放开查看与编辑限制

| 页面 | 改动前 | 改动后 |
|---|---|---|
| 采购入库列表 | 只有「打印 / 删除」，单子点不开 | 操作列新增**详情**弹窗（7 列明细 + 状态徽标 + 打印 + 反审核） |
| 报价单 | 保存只能新建，存错了只能删 | 草稿可**编辑**（左侧表单载入原值）、「已报价」可**反审核**退回草稿 |
| 销售退货 | 只能新建、打印、删除 | 详情弹窗 + **草稿可编辑** + **存为草稿** + 「已退货」**反审核** |
| 购销合同 | 行可点开详情，但不能改 | 草稿可**编辑**（表单整单载入）、「已签订/执行中」可**反审核**（已转单的锁住） |

**最关键的一处不是按钮，是账。** 改造前 `PATCH /sales-returns/{id}/status` 只改状态字面量：
把「已退货」退回草稿后，库存入库和应收冲减**还挂在账上**，单据显示草稿、账本却已经动过。
现在统一收口到 `_sync_sales_return_ledger()`：

- 从 `submitted` 走出去（反审核 / 作废）→ 撤销库存流水 + 撤销应收流水
- 走进 `submitted`（草稿 → 审核）→ 重放库存 + 重写应收
- 一次请求同时带 `status` 和 `items` → 只做一次净动作，不会"回滚一次再加一次"

顺带修掉两个同源洞：

1. `POST /sales-returns` 以前**不管状态一律落账** → 用 `status='draft'` 建出来的单子写着草稿、账上已经加了库存冲了应收；
2. `PATCH` 换明细只重写了库存、没重写应收 → 单据 ¥500、账上还冲 ¥800。

### P2-2 对账单三步走

改造前只有一个「生成草稿」：点下去直接落库，用户没机会在落库前挑行。

现在：

1. 选往来单位 + 账期 → 点 **搜索预览**（新增接口 `POST /statements/preview`，**只取数不落库**）
2. 明细出来，默认全勾，勾掉不参与本单的行
3. 点 **生成对账单（N 行）** → 落库，页面顶部出现绿色「下载 / 打印 PDF」「下载 Excel」「下载 Word」

三步做成了显式的指示条（① 选单位与账期 → ② 搜索预览·勾选 → ③ 生成·下载打印），走到哪一步高亮哪一步。
`preview` 与 `generate` 共用同一个取数函数 `_collect_lines()`，不会出现"预览 10 行、生成 8 行"。

### P2-3 财务流水去冗余

- 删掉「客户 ID / 供应商 ID」两个裸数字输入框（要填 7039 这种 ID，业务人员根本不知道是什么）
- 类型改成 **收（收款/收入）/ 付（付款/支出）**，值仍是 `income`/`expense`，统计口径不变
- 货币、关联订单 ID 收进「更多（可选）」，默认折叠
- 主流程只剩：**选收/付 → 填金额 → 写备注 → 确认保存**
- 要挂往来单位，走订单页的收付款登记，那里会自动带出客户/供应商

### P2-4 全局返回按钮 + 报表日历

- 顶栏新增 **← 返回**：`App.jsx` 维护一个最多 20 层的页内导航栈，任何页面跳转都自动入栈，栈空时不渲染按钮。业务页面一行都不用改（不用逐个二级页塞按钮，也不会出现"没上一页可回"的死按钮）。
- 报表中心日期改版：**年份下拉 + 月份下拉（含"全年"）+ 本月 / 上月 / 今年** 三个快捷按钮；自定义区间收进「自定义」折叠，月末结算与跨年对比仍可用。
- 单一真相源仍是 `reportQuery.date_from / date_to`，年月下拉与快捷按钮都只是往里写值 —— 不另存 state，避免"下拉显示 7 月、实际查的是 6 月"。

### P2-5 导出选列弹窗

客户 / 供应商档案此前**没有导出功能**。现在：

- 「导出 Excel」→ 弹窗勾选列（客户 18 列 / 供应商 15 列，默认勾常用 6 列：编码·名称·联系人·电话·税号·开户行）
- 实时显示「共 N 行数据」与「已选 X / 18 列」
- 零勾选时导出按钮禁用并提示（一列不勾等于给个只有空行的文件）
- 「全选 / 全部取消 / 恢复默认」三个快捷
- 左侧没选分类时按**全量**导出，并在弹窗里用黄条说明「本次导出全部档案」

## 二、接口变动

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/statements/preview` | **新增**。取数不落库，回 `{party_name, items[], line_count, opening_balance}` |
| PATCH | `/api/v1/sales-returns/{id}/status` | 语义变更：现在**联动库存与应收**（见上） |
| PATCH | `/api/v1/sales-returns/{id}` | 支持一次带 `status` + `items`，净动作只做一次 |
| POST | `/api/v1/sales-returns` | `status='draft'` 时**不再落账** |
| PATCH | `/api/v1/contracts/{id}` | `party_id` 加入可改字段（草稿换对方单位）；`party_name` 由前端同步提交 |

## 五、给下一个人的三条提醒

1. **退货单只有 `submitted` 是落账态。** 新增任何"改状态"的入口，一律走 `_sync_sales_return_ledger()`，别直接写 `item.status`。
2. **对账单一律"先预览后落库"。** `/generate` 保留是为了兼容老路径，但界面主入口是 `/preview` → `POST /statements`。
3. **导出列必须是白名单。** 别让前端传任意 `fields` 拼 SQL/取值，列定义只在 `lib/partnerExport.js` 一处。
