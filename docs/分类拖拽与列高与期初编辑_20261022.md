## 问题 1：新建「篷布」报重名 + 二级分类拖不动

### 1a. 重名报错是"假失败"——分类其实建成了

数据库里查到的证据：

```
id=868  篷布  parent_id=11  创建于 2026-10-22 14:42:52
```

14:42:52 正是你点保存的那一刻。也就是说 **第一次请求已经成功**，但你看到的是失败提示。
原因：按钮虽然有 `disabled`，**在输入框里按回车**会直接触发表单提交、绕过按钮 ——
连按两下（或回车 + 点击）就是两次 POST，第二次撞唯一性校验，返回 409「同一上级下已有同类别」。

修复：

| 位置 | 改动 |
|---|---|
| `submitCategory` | 增加 `if (productBusy === 'cat') return;` —— 提交中任何路径都不再发第二次 |
| 409 处理 | 不再抛红字错误，而是**刷新类别树 + 关闭弹窗**，提示「已存在同名类别「X」，已刷新左侧类别树 —— 换个名字，或直接用现有的那个」 |

> 所以「篷布」不用再建，它已经在 中铁一局集团轨道交通…(id=11) 下面了（截图里能看到）。

### 1b. 二级/三级分类没有拖拽手柄

手柄本来就渲染，但 `opacity: 0`，悬停才 `0.55` —— 浅灰小人字形在 260px 的树里几乎不可见。

修复：

```css
.cat-grip { opacity: 0.3; }          /* 常驻淡显，一眼能看出"这里能拖" */
.cat-node:hover .cat-grip { opacity: 0.85; background: rgba(37,99,235,.1); }
```

拖拽事件本身是**每一层都绑**的（`draggable = canDrag && !dupIds.has(id)`），
验收里也真拖了一个三级分类到另一个父级，落库正确。

## 问题 2：行高还是死的、名称还是被截断

### 真相：不是写死 height，是 `ellipsis` 把内容压成单行

`ErpTable` 的 `ellipsis: true` 会在单元格里塞一个
`.erp-table__ellipsis { white-space: nowrap; overflow: hidden; text-overflow: ellipsis; max-width: 280px }`，
所以**行高永远是单行**，长商品名一定被截。

### 改法：给 ErpTable 增加 `wrap` 列选项

```js
// ErpTable.jsx
col.wrap ? 'erp-table__cell--wrap' : ''
```

```css
.erp-table__cell--wrap {
  white-space: normal;
  word-break: break-word;
  overflow-wrap: anywhere;
  line-height: 1.5;
}
```

商品档案的 **名称 / 类别 / 规格** 三列改为 `wrap: true`（不再 `ellipsis`）。
行高由内容决定，图片列（32px 缩略图）也不会被裁。

> ⚠️ 不要给 `td` 设 `height` / `max-height`：`max-height` 在 table-cell 上规范未定义，
> 浏览器直接忽略，反而会退回"一行一个字竖排"。

## 问题 3：期初库存「改这一项」点了没反应

### 真相：数据其实填进去了，但用户看不见

实测点「改这一项」后，表单确实被回填（数量 7480、单价 0.83、备注…），
但表单在**页面上方**、表格在**下方**，视线在表格上根本看不到变化；
按钮文字也还是「加入清单」，没有任何"我在改"的信号。

### 改法：编辑态 + 直接落库

| 项 | 改前 | 改后 |
|---|---|---|
| 点击「改这一项」 | 静默回填 | 表单**滚进视野 + 蓝框闪 1.6s**、提示「已载入「劳保手套」的期初，改完点保存修改」 |
| 按钮 | 永远是「加入清单」 | 进入编辑态变 **「保存修改」**（+「取消编辑」） |
| 保存路径 | 加入清单 → 保存全部（两步） | 「保存修改」**直接 PUT 单条**（按 仓库×商品 upsert） |

后端 `PUT /opening-stock` 是幂等 upsert（只改动 items 里出现的行），所以单条保存安全。
