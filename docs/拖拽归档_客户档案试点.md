# 拖拽归档 · 客户档案试点（2026-10-21）

> 用户诉求：改分类不想再"点编辑 → 弹窗 → 选下拉"。表格里选中几行，直接拖到左侧分类节点上就好。
> 本轮**只开客户档案**，手感确认后再推供应商 / 商品档案（开关在 `PartnersBoard.PARTNER_DND_KINDS`）。

---

## 一、怎么用

| 场景 | 操作 | 结果 |
|---|---|---|
| 单个归档 | 拖表格里任意一行到左侧分类节点 | 松手即归档，提示「已成功移动 1 个客户至「XX」分类」 |
| 整批归档 | 勾选多行，再拖其中任意一行 | 勾了几行就移几行（拖的那行是否在选区里，决定"单条"还是"整批"） |
| 取消归档 | 把行拖到「未分类」节点 | 提示「已成功把 N 个客户移到「未分类」」 |
| 从「未分类」里分拣 | 点「未分类」左侧小三角展开 → 里面直接列出未分类的客户 → 拖走 | 同表格行 |
| 精确修改 | 仍然走「编辑」弹窗里的「所属分类」下拉 | 保留不变（用户要求的兜底） |

视觉反馈：行上 `cursor: grab`，整页拖动期间 `cursor: grabbing`；
经过的分类节点**变蓝 + 左侧蓝条 + 虚线描边**，松手才落库。

## 二、后端接口

```
PATCH /api/v1/customers/batch-category
PATCH /api/v1/suppliers/batch-category      （供应商已就绪，界面暂未开）
Content-Type: application/json

{ "ids": [12, 34], "category_id": 7 }      // 归档到分类 7
{ "ids": [12, 34], "category_id": null }   // 移到「未分类」
```

返回：
```json
{ "moved": 2, "category_id": 7, "category_name": "集团客户" }
```

边界（`tests/test_partner_drag_category.py` 六条用例钉住）：

| 情况 | 结果 | 为什么 |
|---|---|---|
| `ids` 为空 | **400** | "什么都没选也算成功"是事故 |
| **漏传** `category_id` 键 | **400** | 与"显式传 null = 移到未分类"必须能区分；静默清空分类最坏 |
| `category_id` 指向不存在的分类 | **400** | 库里没有外键，不查就会落一个哪儿都查不到的 id |
| `category_id: null` | 200，真的移到未分类 | 合法 |
| `moved` | 真实 UPDATE 行数 | 不是"准备更新几行" |

> ⚠️ 路由必须声明在 `PATCH /customers/{customer_id}` **之前**，否则 `batch-category`
> 会被当成 `customer_id` 解析成 422（商品那边踩过同一个坑，注释留在源码里）。

## 三、前端接线（三处，各管一段）

```
PartnersBoard（表格行 draggable + 拖动状态）
   ├─ rowProps → draggable / onDragStart / onDragEnd
   ├─ 选区判定：拖的行在选区里且选区>1 → 拖整批
   └─ 松手 → onMoveToCategory(ids, categoryId)   ← 由页面薄壳注入

PartnerTree（接住 + 高亮 + 未分类展开）
   ├─ 每个分类行 onDragEnter/Over/Leave/Drop
   ├─ 命中判定认自定义 MIME application/x-erp-partners
   │    （否则从桌面拖个文件进来也会被当成档案去归档）
   └─ 「未分类」可展开：小三角 → 列出 uncategorizedRows，叶子行自己也可拖

App.jsx movePartnersToCategory(kind, ids, categoryId)
   ├─ PATCH /{customers|suppliers}/batch-category（显式带 category_id）
   ├─ setNotice(...)  提示"移了几个、进了哪个分类"
   └─ reloadAfterImport(kind) 刷新列表 → 组件再刷树
```

**为什么不把 fetch 写进 PartnersBoard**：该组件的契约是「只吃 props、不认识
`/customers/{id}`、不发请求」（文件头「职责边界」写了原因）。档案页的增删改一直
是"薄壳拼 endpoint、组件管交互"的分工，拖拽也照这个来。

两套拖拽并存、互不干扰：
- 树的**分类节点**移动（改 `parent_id`）用的是 pointer 事件（`usePartnerDrag.js`）；
- 本轮的**档案行**归档（改 `category_id`）用的是原生 HTML5 DnD。

PASS  库里这条客户的分类真的改了  — category_id=341
PASS  表格行可拖且带上档案 id  — payload=[10668]
PASS  表格行拖拽后同样落库
PASS  全程零页面错误

> 为什么用合成 DragEvent 而不是 `page.mouse`：HTML5 原生 DnD 不走鼠标轨迹，
> puppeteer 的 move 触发不了 `dragstart`。这里验的是"事件接线 + 落库"，不是浏览器拖拽引擎。

## 五、推广到供应商 / 商品（下一步）

| 目标 | 要做的事 |
|---|---|
| 供应商 | 一行：`PARTNER_DND_KINDS` 加 `'supplier'`。后端 `/suppliers/batch-category` 已经在跑，树、行、提示全部复用 |
| 商品 | 不能照抄：`products.category` 存的是**名称字符串**不是外键，接口是 `PATCH /products/batch-category`（传 `category` 名称）；行拖拽 + 树落点可复用，落库那一段要换成商品版 |

建议先让客户档案用两三天，把手感问题（拖拽灵敏度、松手容错、提示文案）收干净再推。
