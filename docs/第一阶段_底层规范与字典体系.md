## 一、需求 1：全局单据号前缀统一

### 1.1 落点

新建 **`app/core/doc_no.py`** —— 前缀的唯一权威。19 处 `_next_doc_no(db, Model, "字面量")` 全部改成 `prefix_of("业务key")`，路由里再出现大写前缀字符串就视为违规（验收台 B1 会扫出来）。

### 1.2 新旧前缀对照（只影响**新生成**的号，历史单据一律不追溯）

| 业务 | 改造前 | 改造后 | 说明 |
|---|---|---|---|
| 销售出库 | `XS` | **`XS`** | 不变 |
| 销售订单 | `XSD` | **`XS`** | ⚠️ 变了：与出库单统一 |
| 采购入库 | `CG` | **`CG`** | 不变 |
| 采购订单 | `CGD` | **`CG`** | ⚠️ 变了：与入库单统一 |
| 对账单 | `DZ` | `DZ` | 不变 |
| 销售退货 | `XSTH` | `XSTH` | 不变 |
| 采购退货 | `CGTH` | `CGTH` | 不变 |
| 报价单 | `BJ` | `BJ` | 不变 |
| 调拨单 | `DBD` | **`DB`** | ⚠️ 变了 |
| 财务流水 | 无号 | **`FL`** | 新增 `flow_no` 列 |
| 合同 | `HT` | `HT` | 不变 |

**为什么订单和出库单可以共用一个前缀而不撞号？** 因为 `sales_orders` 是**同一张表**，取号是"当天同前缀最大流水 +1"，共前缀 = 共用一个序列，本来就不会重复；反过来，分两个前缀才会出现"各自从 001 开始"的跳号。采购侧同理（`purchase_orders`）。

### 1.3 顺手修掉一个会撞号的旧 Bug

改造前的取号是 `ORDER BY order_no DESC LIMIT 1`，**按字符串**取最大。单日一旦超过 999 单写出 `XS202610201000`，字符串序里 `…999` 反而更大 → 算出来还是 1000 → 直接撞号 400。批发场景一次导入上千行并不罕见。

现在改为：取出当天同前缀的**全部**单号，按**数值**取最大再 +1；格式不合规的历史单号（手填的、外部导入的）**不参与**取号，避免一条脏数据把流水顶到天上。验收台 A2/A3/A4 专门盯这三种情况。

### 1.4 财务流水号 FL

`financial_transactions` 新增 `flow_no`（`VARCHAR(40)`，可空，历史行留空不追溯），格式 `FL20261020001`。五处创建点全部覆盖：单据自动写流水、人工登记收支、红冲红字行、账户转账（一借一贷各一个号）、发票生成费用流水。

⚠️ 生成前强制 `db.flush()`：会话是 `autoflush=False`，不 flush 的话同一事务里刚 `add()` 的流水查不到 —— 转账单写两笔会拿到同一个号。

**字典项为什么用字符串 `dict_type` 关联而不是外键 id**：前端只要一个 type 就能取整列候选，不必先查类型表拿 id；字典是配置，不需要被单据外键引用，也就没有级联删除负担。

| dict_type | 名称 | 候选 |
|---|---|---|
| `fund_account` | 资金账户 | 现金 / 基本户 / 一般户 / 微信 / 支付宝 / 备用金 |

> 三者分工说清楚，避免以后又混：**付款方式** = 用什么付（现金/转账/承兑）；**结算方式** = 怎么结（现结/月结/账期）；**资金账户** = 从哪个账户走（真实余额仍在现金银行页的资金账户表里，字典只做登记时的默认候选）。

**几个刻意的取舍，请你确认**：

1. **只用整数（mm / pt）**，不用小数。渲染最终落到整数像素/缇，1mm 精度远超肉眼，"12.0000001mm" 这种值不该进库。
2. **加了 4 条 CHECK 约束**：纸张只认 4 种；边距 0~50mm；字号 6~28pt；`CUSTOM` 必须给宽高。前端校验会被绕过（直接 SQL / 接口），数据库这道必须留。
3. **没做"字段级动态列配置"**。老系统那种"打印字段表"把列宽、合计位置、换页阈值都搬进数据库，数据库多一个字段渲染器就多一种猜错的组合 —— 出一张格式错乱的发票比"模板不能随便改"严重得多。本项目仍是「模板配置表 + 固定渲染器」，这次只是把**外观参数**补齐。
4. **渲染器要同步改**：`app/services/pdf_render.py` 目前不读这些新列。确认表结构后，下一阶段做"模板 → PDF"接线，届时每加一项都必须有渲染点，否则就是"改了没反应"的假参数。
