# 树内平铺客户 + 手风琴折叠 + 拖拽后列表为空修复（2026-10-21 · 第五轮）

> 三个闭环：① 树不再是纯目录，展开分类就能看见挂在下面的客户；② 展开一个一级节点，
> 其它同级节点连同子孙和客户一起折叠（手风琴）；③ 拖完右侧列表不再"假装为空"。
> 顺手清掉了测试脏数据。
> 交付版本 **v151 · 20261021-2119**（纯前端 + 一次数据清理，`Ctrl + F5` 即可）。

## 问题 1：树内平铺客户 + 手风琴

### 做法

`PartnerTree` 新增两个入参（都由看板给数据，树只负责画）：

```jsx
rowsByCategory={rowsByCategory}   // { [categoryId]: 客户[] }
onPickRow={(row) => onSearch(row.name)}   // 点叶子 → 右表按名字定位
```

**插在哪儿**：先序遍历里，某节点的子树到"下一个深度 ≤ 自己深度"的行为止 —— 叶子挂在
**整棵子树之后**。所以视觉顺序是"子分类先、文件后"，跟资源管理器一致。

**手风琴**：`toggle()` 展开某节点时，把**同一个父级下**其它已展开的兄弟从 `expanded` 里删掉。
只折叠兄弟、不动父级链 —— 否则展开子级会把刚点开的父级自己关掉。

### 踩到的坑：纯叶子分类永远展不开

`buildVisibleRows` 里 `row.isOpen = expanded.has(id) && hasChildren`，而 `hasChildren`
只认**子分类**。于是「机具分公司」这种"没有子分类、只有 1 个客户"的节点永远 `isOpen=false`，
它的客户永远看不到。改成：

- 叶子数据用 `expanded.has(row.id)` 直接判；
- 箭头/`aria-expanded` 的条件从 `row.hasChildren` 改成 `row.hasChildren || leafRowsOf(id).length`。

现在"有客户就能展开"，箭头会转、点了就列出客户。

## 问题 2：拖拽后右侧列表"假装为空"

用户看到的是：拖拽提示成功，右侧列表空空如也，还挂着
「已选中 N 项，但不在当前筛选内」。

两个原因叠加：

| 原因 | 表现 | 修法 |
|---|---|---|
| 拖拽成功后**没有清勾选** | 被拖走的行已不在原筛选里，批量条一直喊"不在当前筛选内" | 成功后 `setSelectedKeys([])` |
| 切换筛选时数据还是旧的（`reload` 是异步的） | 有一段时间 `category_id` 还是旧值 → 目标分类过滤后 0 行 | `movePartnersToCategory` 里先做**乐观更新**（本地把这几行 `category_id` 改掉），再 reload 校准 |
