## 二、导入前的判断（为什么不是"照单灌入"）

跑 `--dry-run` 后发现一件必须叫停重算的事：**剩余 18 张源单，每一张都横跨 2~3 个工程**。

`SalesOrder` 只有一个 `customer_id`。整张导进去，`build_groups` 会取第一行的工程当客户 ——
等于把另外两个工程的应收**全挂到第一个工程头上**，对账必错，而且是"看着成功、账是错的"。

所以本轮给执行器加了 `--split-cross`：

```
一张源单（跨 3 个工程）
   → 拆成 3 张系统单，每张只含本工程的明细
   → 金额总和不变（只是分配对象正确）
```

备注写成 `历史导入|源单号=X|工程=Y|来源=z.xls`，幂等键随之从"源单号"升级为"源单号#工程"，
同时**兼容上一批整单导入的旧键**（否则同一张单会被导第二遍，金额直接翻倍）。

> 关于「45 组重复单暂缓」：当前 plan 口径是 **55 条重复行、涉及 19 个源单号**。
> 逐条核对后确认：**这些"重复"全部是同一商品在同一单里分属不同工程**（`同客户重复 = 0 条`），
> 拆单后它们是**各自工程各自的明细**，不是重复记账。唯一真·同工程重复的是
> `XS202506160006`（见第六节），而它在第一批就已入库，本轮未再触碰。

## 六、遗留与建议（需要业务确认，不是技术问题）

### 1. `XS202506160006` 疑似重复计价 ¥8,505.20

第一批已入库的这张单里，有 3 行**同工程、同商品、同数量、同单价**出现两次：

| 商品 | 数量×单价 | 出现次数 | 疑似多算 |
|---|---|---|---|
| E30浸胶手套-9码 | 2750 × 2.20 | 2 | ¥6,050.00 |
| 黄边线手套 | 1800 × 1.10 | 2 | ¥1,980.00 |
| 帆布手套（普） | 216 × 2.20 | 2 | ¥475.20 |
| **合计** | | | **¥8,505.20** |

系统如实反映了源表（两行都入库）。**如果实际只发了一次货**，需要冲销这 3 行：
走「反审核 → 改单 → 重新审核」或做一笔红字应收，金额 ¥8,505.20。

### 2. 跨工程拆单后的对账单

一封对账单（源单号）现在可能对应 2~3 张系统单。做客户对账单时按**客户**取数即可，
不需要按源单号取 —— 源单号只留在备注里做追溯。

### 3. 建议给历史单打一个标记

目前靠备注 `历史导入|` 前缀区分。若要按报表维度统计"历史 vs 新单"，建议后续加
`SalesOrder.source = 'history'` 字段（本轮没加，避免动表结构）。
