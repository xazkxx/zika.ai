## 3. 后端路由：只有 3 类写法会炸

改完 Schema，请求体里的金额就都是 `Decimal` 了。**下面三类必须改，其余基本安全。**

### 3.1 字面量 float 参与运算 → `TypeError`

```python
# ❌ app/api/v1/routes/erp_invoice.py:190
if items and abs(sum(item["amount"] for item in items) - total_amount) <= max(0.05, total_amount * 0.005):

# ✅
from app.core.money import dec, money
diff = abs(dec(sum(item["amount"] for item in items)) - dec(total_amount))
if items and diff <= max(dec("0.05"), dec(total_amount) * dec("0.005")):
```

同型：`erp_invoice.py:118`、`:149`（`qty * price - amount` 里的容差比较），
`app/services/contract_ocr.py:241`（`money * 0.005`）—— 后者走的是 OCR 的 float 明细，**可以不改**，
但为了口径统一建议一并 `dec()` 包一层。

### 3.2 `sum(..., 0.0)` 起始值

```python
# ❌
total = sum(rows, 0.0)
# ✅
from app.core.money import ZERO, sum_money
total = sum_money(rows)          # 或 sum(rows, ZERO)
```

> 注意：`sum([Decimal, Decimal])` **不写起始值**是安全的（从 int 0 起算，`0 + Decimal` 合法）。
> 只有显式写了 `0.0` 才炸。全仓目前**没有**这种写法（已 grep 确认），但新增代码别写。

### 3.3 出库前必须 `float()`

已经做对了的地方**不要动**（这是"外部接口仍给 float"的设计）：

```python
float(order.total_amount or 0.0)        # erp_purchase.py:470  ✅
float(r.amount or 0.0)                  # erp_finance.py:195、:580-585  ✅
float(item.total_amount or 0)           # erp_invoice.py:_invoice_to_dict  ✅
```

写 JSON 时**绝不能直接塞 Decimal**（`json.dumps(Decimal)` 抛 `TypeError: not JSON serializable`）。
检查点：

```bash
grep -rn "json.dumps(" app/api/v1/routes/*.py app/services/*.py | grep -v ensure_ascii
```

目前只有 `invoices.items_json = json.dumps(items)` 一处，`items` 来自请求体 JSON（元素是 float），
改完 Schema 后 `InvoiceCreate.items: list[dict]` 仍是 float，**安全**。

### 3.4 已经能自动兼容的（不用改，但要知道）

| 位置 | 为什么安全 |
|---|---|
| `erp_common.py:600 amount_to_chinese` | 内部第一行就是 `float(amount or 0.0)` |
| `erp_finance.py:102/212/224` 的 `round(sum(...), 2)` | `round` 接受 Decimal，返回 Decimal |
| 所有 `func.sum(...)` 在 SQL 里算的 | 聚合发生在数据库，返回 Decimal 后由 `float()` 兜住 |

## 7. 我为什么不替你按下这个开关

`Model/Schema` 一改，后端就必须重启；而重启的那一刻如果 SQL 还没 COMMIT，
员工点开单 → `Decimal * 0.13` → 500。你现在的库里还没有"金额超 2 位小数"的脏值（我核过，
三个 schema 合计 0 行），但这个切换窗口是硬的。

所以：**SQL 你跑完说一声，我把 §1–§4 一次性落下去、重启、跑体检、再跑 36+20 两套验收台**，
大概 10 分钟。在那之前，我把两个新模块和这两份 SQL 先放好，不动任何运行时逻辑。
