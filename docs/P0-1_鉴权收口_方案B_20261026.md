## 一、问题有多大（先量化，再动手）

`scripts/audit_auth_routes.py` 第一版干的就是这件事：把 `app.main:app` 的路由表走一遍，
逐个依赖树找 `get_current_user` / `require_roles`，把"没有身份校验"的端点列出来。

结论：**320 个 `/api/v1` 端点里 318 个无身份校验**。也就是说只要能访问到 8010 端口，
不登录就能读全量客户/供应商/商品、改单、导出报表。前端那个登录页只是"前端的礼貌"，
后端一律照单全收 —— 把 `localStorage` 清掉、或者直接用 `curl`，什么都能看。

三个已经被利用逻辑上"可自证"的后门：

| # | 后门 | 后果 |
| --- | --- | --- |
| ① | `POST /api/v1/auth/register` 的 `role` 由请求体决定 | 任何人 `{"username":"x","role":"admin"}` 直接开管理员账号，连登录都不用 |
| ② | `GET /api/v1/auth/users` 无任何校验 | 不登录就能拉全量账号（用户名/邮箱/角色），拿到清单再撞密码 |
| ③ | `SECRET_KEY` 默认值 `change-me-in-production`（`.env` 里根本没配这一项） | HS256 密钥是公开字符串 → 谁都能自己签一张 `sub=admin, role=admin` 的 token |

③ 最致命：**前两条只是"绕过登录"，③ 是"伪造登录"**，而且不需要碰任何接口。

## 二、为什么不用逐路由 `Depends(get_current_user)`

在 318/320 的比例下这条路走不通，三个理由都不是"麻烦"：

1. **改不完**：320 个函数要一个个加依赖，漏掉的那一个不会报错、不会失败，只会继续裸奔。
2. **验不完**：没有一份"每个端点都必须鉴权"的可执行清单，就无法证明改完了。
3. **默认值错**：逐路由加锁的默认状态是"不安全"——以后新加的路由照样默认裸奔。
   这是设计方向的问题，不是工作量的问题。

所以反过来做：**默认拒绝、白名单放行**。新增路由自动受保护；忘记加白名单的代价是
"访问被拒"（立刻可见、会报错），而不是"数据被读走"（静默、事后才知道）。

## 三、方案 B 怎么落地

### 3.1 中间件位置

`app/main.py` 里三个中间件的注册顺序（**Starlette：后注册 = 更靠外**）：

```
操作日志(_operation_log_middleware)  ← 最外层：401 也要留痕
    └── 鉴权网关(auth_gate_middleware)
            └── 租户上下文(_tenant_context_middleware)
                    └── 路由
```

为什么卡在这两层之间：

- **在租户上下文之上**：匿名请求不必白建一次账套 schema 上下文（少一次无意义的 SET search_path）。
- **在操作日志之下**：越权尝试本身也必须留痕。
  `tests/test_system_templates_and_logs.py` 里那条用例钉着的就是这条口径：
  `401` 也要写进操作日志、`username` 为空。网关放到最外层会让这类攻击在日志里完全消失。

### 3.2 判定与语义

| 情形 | 返回 | 说明 |
| --- | --- | --- |
| 没带 / 带空 / 格式不对 | `401` + `WWW-Authenticate: Bearer` | 中文 `detail`，前端能直接显示 |
| 签名错 / 过期 | `401` | 同上 |
| 签名对，但账号已被删除 | `401` | 提示重新登录 |
| 签名对，但账号被停用 | `403` | **不能是 401**：用户没输错密码，是账号被停 |
| 签名对、账号在、未停用 | 放行 | `request.state.auth_user` 供下游复用 |

关键一点：**除了验签，还要回库确认账号仍在且未停用**。只看签名的话，被停用的人手里的旧
token 还能继续用到过期（默认 60 分钟），「停用」按钮就等于没按。

### 3.3 `auth_mode`

`settings.auth_mode` 默认 `enforce`。`off` 只留给应急排障（例如现场要临时比对裸接口返回），
一旦生效会在控制台吼一次：`[security] 警告：auth_mode=off，/api/v1 接口不校验身份`。
**测试跑的是 `enforce`**，不靠关开关让用例变绿（见第五节）。

## 四、白名单（这份清单就是安全边界）

`app/core/auth_gate.py` 里只有 3 条精确路径 + 1 段前缀，加一条都要在提交说明里讲清理由：

| 白名单 | 作用 | 为什么必须放行 |
| --- | --- | --- |
| `/api/v1/health` | 探活 | 桌面壳/负载均衡在**登录前**就要轮询它等后端就绪 |
| `/api/v1/auth/login` | 登录 | 要发 token 的接口不能先要 token |
| `/api/v1/auth/register` | 自助注册 | 放行到路由层，是为了让路由自己回 **403 + 中文说明**（默认已关闭）；被网关拦成 401 的话用户只会看到"未登录"，反而找不到正确入口 |
| 前缀 `/api/v1/uploads/products/` | 商品图 | 前端是 `<img src="/api/v1/uploads/products/xxx.png">`，**浏览器发这种请求不会带 Authorization**，拦了就是整页缩略图全空。只放开这一个只读目录，业务数据一律不放 |

`scripts/audit_auth_routes.py` 里另存了一份 `EXPECTED_PUBLIC_PATHS/PREFIXES` 作为**独立副本**：
白名单被加宽（多一个路径/前缀 = 多一个后门）`--strict` 直接 exit 1。
两份清单不一致同样报错——这就是"改安全边界必须过门禁"的意思。

## 五、三个后门的修法

### ① 自助注册（`app/api/v1/routes/auth.py`）

两道锁，缺一不可：

- `settings.allow_self_register` 默认 **False** → 直接 403，提示"请让管理员在「系统设置 → 用户管理」里创建账号"；
- 即便显式打开（首次部署/联调），`role` 也**写死 `staff`**，请求体里的 `role` 一律忽略。
  要开管理员，只能在已登录的管理员会话里走 `POST /system/users`（那条路本来就有角色闸）。

### ② `/auth/users` 列全表

原来连 `Depends(get_db)` 之外什么都没有。现在挂上 `require_roles("admin")`。
用户管理页走的是 `/system/users`，所以这条对前端零影响。

### ③ JWT 默认密钥（`app/core/config.py`）

`.env` 里从来没有 `SECRET_KEY`，于是全站一直用公开默认值签名。现在的处理：

- 仍是默认值时 → 生成 `secrets.token_urlsafe(48)` 并**落盘**；
- 落盘位置：`ERP_SECRET_FILE` 指定，否则 `~/.erp_core/secret_key`（打包成 exe 后 `_MEIPASS` 只读，不能放那儿）；
- 为什么要落盘而不是每次随机：密钥一变，所有人手上的 token 立刻失效（表现为"刚登录完又被打回登录页"）；
- 读不走/写不进时退化成"本次进程内随机"——宁可重启后重新登录一次，也**绝不**退回那串公开默认值。

> 已显式配了 `SECRET_KEY` 的环境（比如以后的正式服务器）行为完全不变。

## 六、测试怎么改的（这是本次最容易做错的地方）

存量 61 个文件、几百条用例全都在 `TestClient(app)` 上直接打业务接口，没有一条带过登录语义。
收口后它们会集体 401。改法**不是**去动那几百条用例，而是在 `tests/conftest.py` 里：

1. `_install_authed_test_client()` 把 `fastapi.testclient.TestClient` 换成一个
   "默认带管理员 token"的子类（token 用 `admin` + 本进程真实密钥签发，7 天有效）；
2. 逐请求传的 `headers={'Authorization': ...}` 优先级更高 → 需要验证"匿名应被拒"的用例
   传 `{"Authorization": ""}` 就能把默认值抵掉；
3. **被测代码跑的是生产口径**（`auth_mode=enforce`），没有靠环境变量关鉴权让用例变绿；
4. `ERP_SECRET_FILE` 在 conftest 顶层指向系统临时目录，测试不污染用户目录；
5. 关键顺序：`_install_authed_test_client()` 必须在 `pytest_sessionstart` 里（换库之后）才 import `app.*`。
   如果在 conftest 顶层就 import，`settings` 会在 `DATABASE_URL` 被换成测试库**之前**定型，
   整场测试会打到生产库 —— `.env` 里 `DATABASE_URL` 就是生产库，这条踩了很难发现。

被显式改写的 6 条存量用例（都只是**把"匿名"表达清楚**，断言口径没降）：

| 用例 | 改法 |
| --- | --- |
| `test_agent_dispatch.py::test_dispatch_requires_auth` | 加 `headers={"Authorization": ""}` |
| `test_menu_reorder.py::test_reorder_requires_admin_token` | 同上 |
| `test_system_users.py::test_system_endpoints_require_authentication` | 4 条断言统一用 `anon` 头 |
| `test_system_templates_and_logs.py::test_print_templates_require_admin` | 同上 |
| `test_system_templates_and_logs.py::test_log_endpoints_require_admin_but_writes_are_still_recorded` | 同上（并因此发现"网关必须在日志之内"） |
| `test_employee_and_opening.py::test_department_options_open_to_any_logged_in_user` | 同上 |

新增 `tests/test_auth_gate.py`（8 条）：匿名 401、空头 401、坏 token 401、好 token 通过、
白名单（health / login / register / 商品图）、停用账号 403、`auth_mode=off` 放行。
**为什么必须有**：收口后绝大部分用例靠注入 token 才跑得起来，"鉴权坏了"和"鉴权正常"
在结果上看起来一模一样 —— 这 8 条刻意用假 token 把默认值抵掉，专门验"匿名到底会不会被拒"。

`tests/test_auth.py` 也重写了：原来那条用例断言的**正是后门本身**（不登录注册出一个
`role=admin` 并 201 成功），现在断言 403 + 账号确实没落库 + 打开开关也拿不到 admin。

## 八、运维须知（交付后会被问的几件事）

1. **首次启动会多一个文件**：`C:\Users\<用户>\.erp_core\secret_key`（或 `ERP_SECRET_FILE` 指定处）。
   删了它 = 所有人退出登录，需要重新登录 —— 不是故障。要固定密钥就给环境变量 `SECRET_KEY`。
2. **默认管理员仍是 `admin / Admin123`**：网关解决的是"没登录也能看见"，不是"默认密码太弱"。
   交付时必须改掉（这次没有强制改密流程，属已知缺口，见第九节）。
3. **`auth_mode=off` 只用于排障**，跑起来会在控制台打警告；生产一律 `enforce`（默认值）。
4. **以后要加白名单**：改 `app/core/auth_gate.py` **且**同步改
   `scripts/audit_auth_routes.py` 的 `EXPECTED_PUBLIC_PATHS/PREFIXES`，并在文档里写理由。
   只改一处会被 `--strict` 拦下——这是故意的。
5. **前端新加 `fetch` 必须带 `authHeaders()`**：漏了就是运行期 401（页面空一块），
   本地开发不容易发现（本地可能还存着旧 token）。本次已全量核查 265 处。
6. **多账套不受影响**：`users` 是全局表，网关查它不依赖租户 schema；
   业务数据仍在各自账套里，鉴权只回答"你是谁"，不回答"你能看哪家"（后者由 token 里的 `company` 决定）。

## 九、这次**没有**解决的（别当成已经解决）

| 缺口 | 现状 | 建议下一步 |
| --- | --- | --- |
| 默认密码 | `admin/Admin123` 仍可登录，首次登录不强制改密 | 加"首次登录必须改密"闸（`must_change_password` 列 + 前端拦截） |
