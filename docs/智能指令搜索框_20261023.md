# 🤖 智能指令搜索框（/agent/dispatch）— 2026-10-23

工作台最顶部多了一条输入框：打一句人话（"给我湖南华邦的对账单" / "蒲白750 的合同"），
系统认出**要什么**、**哪家单位**，把结果以悬浮卡片列出来，每个卡片带"能干活"的按钮。

> 定位：**找得到、看得见、跳得过去**。不替代「购销合同」「增强对账单」页面 ——
> 真正的生成/审核/留痕仍在那两页完成（那里有各自的校验、编号与权限）。

---

## 一、一句话是怎么变成结果的

```
"给我湖南华邦的对账单"
   │
   ├─ ① 解析（规则）      type=statement  party_query=湖南华邦  confidence=0.9
   ├─ ② 认人（模糊）      湖南华邦 → 湖南华邦建设有限公司（customer #7039, matched_by=contains）
   ├─ ③ 取数（复用引擎）  该单位未结清单据（欠款>0）+ 已生成对账单
   └─ ④ 组织              matched_data[] + summary + goto{page, party, scope} + message
```

### 1. 解析（`app/services/agent_command.py::parse_command`）

* 类型词表：对账单/对账/结算单/欠款/未结清 ↔ 合同/协议/购销合同/报价单；
* 动作：出现「生成/新建/做一份/创建」→ `action=create`，否则 `list`（**只标记意图，不执行写操作**）；
* 抽名字：先剥后缀型词（"销售合同"），再剥动词/介词（"给我/给/和/跟/查/找/生成"），
  最后收掉"的/了/吧"。

> ⚠️ 剥离顺序是踩出来的：早先没有单独的「给」，"给湖南华邦的对账单"被抽成
> "给湖南华邦"，查不到人。现在 `NOISE_WORDS` 长词在前、单字在后。

### 2. 认人（`resolve_parties`）

| 命中方式 | 例子 | 分数 |
|---|---|---|
| 全称相等 | 湖南华邦建设有限公司 → 同一条 | 100 |
| 名字包含查询 | 湖南华邦 → 湖南华邦建设有限公司 | 60~90（按长度比例） |
| 查询包含名字 | 你多打了"有限公司" | 55 |
| 简称 / 联系人 / 业务员 / 电话 | 周广平（联系人） | 40~90 |

客户与供应商两张表一起查（id 会撞，所以结果里带 `type`）。
一句里塞两个名字（"湖南华邦 周广平"）时，整串匹配不上会**按词从长到短再试一次**。

### 3. 取数：绝不算第二套数

* **对账单**：直接调 `erp_statement._build_fusion_rows`（对账单页面用的同一个聚合引擎），
  取 `remaining_debt > 0` 的单据。时间窗从 2015-01-01 到今天，历史欠款不会漏。
* **合同**：只读 `contracts` 表自己的字段（不做跨表推断）。
* 两个分支都**不写库**：没有任何 create/patch。

### 4. 跳转参数（前后端契约）

| 意图 | `goto` |
|---|---|
| 对账单 | `{page:'statements-editor', scope:'out'\|'in', party:'c:<客户id>'\|'s:<供应商id>', party_id, party_name}` |
| 合同 | `{page:'contracts', keyword:'<单位名>', party_id, party_name}` |

`party` 的 `c:` / `s:` 前缀**必须**带 —— 客户与供应商 id 会撞，只有数字分不清是谁。

## 二、前端

`frontend/src/components/agent/SmartCommandBar.jsx` + `smartCommand.css`，
挂在 `OverviewPage`（工作台）**欢迎横幅上方**。

* 结果面板是 `position: absolute` 的**悬浮层**（不把下面的 KPI 卡片推下去）；
* 卡片分三组：**已生成的对账单**（单号/期间/金额/状态 + 打开预览/生成 PDF/去修改）、
  **未结清单据**（单号/日期/单据额/欠款 + 去生成对账单）、**合同**（单号/签订日期/金额/状态 + 打开预览/导出 Word/去确认）；
* 命中单位用 `<mark>` 高亮："你到底给我挑的是哪一家"必须一眼看到（打简称时尤其重要）；
* 认不出人时给"是不是：…"候选 chip，点一下用全名重查；
* 预览：对账单 → `GET /statements/{id}`；合同 → `POST /contracts/document/preview`
  （内置《产品买卖合同（简易版）》），标题栏标出**模板名**（合同自身标题可能是"克拉玛依…采购合同"）。

### 导出通道

| 目标 | 走法 | 为什么 |
|---|---|---|
| 对账单 PDF | `GET /print/statement-record/{id}` + `Accept: application/json` | PDF 直链会被浏览器阅读器接管，拿回空 body（同打印中心） |
| 合同 Word | `GET /exports/word/contract/{id}` → blob，校验大小与 `PK` 头 | docx 不会被拦，但要挡 0 字节 |

### 跳页并预填

`App.jsx::agentGoto`：

* 对账单 → `setStatementPreset({scope, party, nonce})` + `setSelectedTab('statements-editor')`，
  并把 `nonce` 塞进 `<StatementEditor key={...}>`，**已经在那一页时也能重建**；
* 合同 → `setContractKeyword(name)` + `refreshContracts(name)` + 切页。

`StatementEditor` 新增 `initialParty` prop，等 `parties` 名单里真有这一项才赋值 ——
否则下拉会短暂显示裸 id（"c:7039"），看着像认错了人。

> ⚠️ 那个 `useEffect` 必须放在 `parties` 的 `useMemo` **之后**。
> 放前面会在 deps 里引用尚未初始化的变量，实测直接白屏：
> `ReferenceError: Cannot access 'parties' before initialization`。

## 三、接本地大模型（预留）

`agent_command.py` 末尾留了 `parse_command_via_llm()` 的完整实现（注释状态）：
装了显卡 / 起了 Ollama 后，把 `dispatch()` 里那一行换成它即可，
**认人、取数、goto 全都不用改** —— 只要它返回同样的
`{type, action, party_query, confidence, parser}`。

提示词写在注释里，要点是 `format: "json"` + `temperature: 0`，且**失败必须回落到规则版**
（模型没起/超时不能让搜索框报错）。
